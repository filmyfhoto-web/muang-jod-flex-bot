# stationery-bot

บอท LINE OA ช่วยตอบลูกค้าร้านเครื่องเขียน (แยกจากบอท "ม่วงจดให้" ที่อยู่โฟลเดอร์ด้านนอก ไม่ใช้โค้ดร่วมกัน)

ตอบจากข้อมูลที่ร้านกรอกเองใน `data/shop.json` — ไม่ใช้ AI:

- **สินค้า** พิมพ์ชื่อ/ชื่อเรียก → บอกราคา ราคายกจำนวนมาก และมี/หมดสต็อก
- **คำถามทั่วไป (FAQ)** เวลาเปิด ที่ตั้ง จัดส่ง ชำระเงิน โปร ใบเสร็จ — จับจากคำสำคัญ
- **ตอบทันที** (ตั้งรอได้ที่ `replyDelaySeconds` 0 = ทันที)
- **ติดต่อแอดมิน** ลูกค้ากดปุ่มดำ "ติดต่อแอดมิน" → การ์ด "ติดต่อ หญิง / ฟิล์ม / พี่ปิ่น" (มีรูปโปรไฟล์ไลน์ของแต่ละคน) (`contact` ใน `data/shop.json`)
  - ลูกค้ากดชื่อ → บอท**เงียบ**กับลูกค้าคนนั้น (20 นาทีที่ไม่มีข้อความ แล้วกลับมา หรือลูกค้าพิมพ์ "เมนู") และมี**การ์ดแจ้งเตือนเด้งเข้าไลน์ของคนที่ถูกเลือก**
  - ข้อความที่บอทไม่เข้าใจ และรูป/สลิป → บอท**ไม่ตอบลูกค้า** แต่ส่งการ์ดแจ้งเตือนหาแอดมิน**ทั้ง 3 คน** (ไม่เกิน 1 ครั้งต่อลูกค้าต่อ 10 นาที: `notifyAllMinutes`)
  - ใส่ `userId` ของแต่ละคนใน `contact.people` (ให้แต่ละคนเพิ่มเพื่อน OA แล้วพิมพ์ "ไอดีฉัน")
  - ข้อความแจ้งเตือนเป็น push ของ OA นับโควตาข้อความรายเดือน (ปิดได้ด้วย `"notify": false` ถ้าใช้แจ้งเตือนของแอป OA แทน)
- ปิดบอทชั่วคราว: `"paused": true` หรือแอดมินพิมพ์ "ปิดบอท" (ดู `ADMIN_USER_IDS`) ระหว่างรอ 90 วินาที จะยกเลิกคำตอบที่ค้างอยู่
- หัวข้อที่ยังไม่มีข้อมูลจริง ปิดไว้ด้วย `"enabled": false` (FAQ) / `"productsEnabled": false` (สินค้า)
- แก้ `data/shop.json` ได้เลยโดยไม่ต้อง restart

## ฟีเจอร์ของแอป NATTA GROUP (บอทตัวเดียว)

บอทนี้ตอบแทนบอทของแอป (`line-bot` บน Supabase) ได้ด้วย — โค้ดอยู่ใน `src/app/` (ยกมาจากบอทของแอปรุ่นที่ใช้งานอยู่ แก้เฉพาะจุดที่ทำเครื่องหมาย `[render]`):

| ลูกค้าส่งมา | บอทตอบ |
|---|---|
| "ขอใบสั่งซื้อ NT-0044" / "ขอการ์ดยืนยัน NT-0044" / "📦 ส่งออเดอร์ NT-0044 …" | การ์ดใบสั่งซื้อ / การ์ดยืนยัน (เฉพาะเจ้าของออเดอร์หรือพนักงาน; ถ้าร้านยังไม่ยืนยัน บอก "ร้านกำลังตรวจสอบ…") |
| เพิ่มเพื่อน · ข้อความแรกหลังเงียบไป 60 นาที · พิมพ์ "เมนู" | ข้อความทักทาย + การ์ดเมนูรูป 3 ช่อง + ปุ่มลัด (`menu_card`) |
| "คุยกับแอดมิน" → กดชื่อ | การ์ดเลือก เจ้ปิ่น/หญิง/ฟิล์ม → ยืนยัน แล้วบอทเงียบ 24 ชม. (พิมพ์ "เมนู" กลับมา) และคนที่ถูกเลือกได้การ์ดแจ้ง (`admin_pick`) |
| "ส่งเอกสารโครงการ" / ส่งไฟล์ | การ์ดลิงก์หน้าส่งเอกสาร + ขั้นตอนรับไฟล์/แก้ไขเอกสารทางแชท เก็บเข้า Storage และ Drive (`docs`) |
| อย่างอื่น | บอทเดิมของไฟล์นี้ตอบเหมือนเดิม (เวลาเปิดร้าน · สั่งของ · อุปกรณ์การเรียน · ที่ตั้ง · ขอบคุณ · รูป/ไฟล์ …) |

ลำดับต่อ 1 ข้อความ (กันตอบชนกัน): ขอการ์ดออเดอร์ → คุยกับแอดมิน/เลือกชื่อ → ขั้นตอนเอกสาร → ช่วงคุยกับแอดมิน (เงียบ) → เมนูร้าน → ที่เหลือเป็นของบอทเดิม. ถ้าการ์ดเมนูเปิดอยู่ บอทเดิมจะไม่ถามซ้ำ "ต้องการติดต่อใคร" ตอนทักครั้งแรก และไม่ตอบ "สวัสดี" เฉย ๆ (ไม่ให้มีเมนู 2 อัน)

**เปิดใช้ (ฝั่งเจ้าของ):**
1. ที่ Render → Environment ตั้ง `SUPABASE_URL` (ที่อยู่โปรเจกต์ Supabase ของแอป) และ `SUPABASE_SERVICE_ROLE_KEY` (ฝั่งเซิร์ฟเวอร์เท่านั้น) — `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_CHANNEL_SECRET` ใช้ตัวเดิม ไม่ตั้ง 2 ตัวนี้ = ฟีเจอร์ของแอปปิด บอทเดิมทำงานเหมือนเดิมทุกอย่าง
2. ตัวเปิด/ปิดแต่ละอย่างอยู่ในแอป (หลังร้าน → ตั้งค่า LINE) = แถว `app_config.line_bot`: `menu_card` (การ์ดเมนู), `admin_pick` (เลือกแอดมิน), `docs` (เอกสาร; `"trial"` = เฉพาะพนักงาน), `enabled` (ปิดทั้งหมด) — บอทอ่านค่าใหม่ทุก ~15 วินาที ไม่ต้อง restart. การ์ดออเดอร์ทำงานเสมอเมื่อตั้งข้อ 1 แล้ว
3. ถ้าอ่านแถวตั้งค่านี้ไม่ได้ (ฐานข้อมูลล่ม) ฟีเจอร์ของแอปหยุดเอง บอทเดิมตอบต่อ ไม่ส่งเมนูรัว ๆ

ใช้ `GET /health` ดูว่าเปิดอยู่ไหม: `"app":"off"` = ยังไม่ได้ตั้ง 2 ค่าข้อ 1 · `"no-db"` = ตั้งแล้วแต่อ่านฐานข้อมูลไม่ได้ (ตรวจที่อยู่/กุญแจ) บอทเดิมยังตอบตามปกติ · `"on"` = ใช้ได้ (`"assist":"ready"` = ตัวตอบที่หน้า Studio แก้ได้พร้อมใช้) · `"build"` = เลขคอมมิต 7 ตัวที่เซิร์ฟเวอร์รันอยู่ (ไว้ดูว่า deploy ล่าสุดเสร็จหรือยัง). Webhook ของ LINE ยังชี้ที่บอทนี้ที่เดียว ไม่ต้องเปลี่ยน

คำสั่งของแอดมินที่เป็นของบอทนี้ (**"ติดตั้งเมนู" · "ลบเมนู" · "ปิดบอท" · "เปิดบอท" · "แอดมินออนไลน์/ออฟไลน์" · "โควตา" · "ไอดีฉัน"**) ข้ามฟีเจอร์ของแอปไปหาบอทนี้ตรง ๆ — การ์ดเมนูร้าน/การ์ดเลือกแอดมินจะไม่มาแย่งตอบ (แอดมินต้องอยู่ใน `contact.people` หรือ `ADMIN_USER_IDS`; "ไอดีฉัน" ใครพิมพ์ก็ได้) และตอนที่แอดมินสั่ง "ปิดบอท" อยู่ คำสั่ง "เปิดบอท" ยังใช้ได้ ส่วนลูกค้าไม่ได้คำตอบเลย

## รัน
```bash
cp .env.example .env   # ใส่ LINE_CHANNEL_ACCESS_TOKEN / LINE_CHANNEL_SECRET
npm install
node --env-file=.env src/server.js
npm test
```
ตั้ง Webhook URL ใน LINE Developers เป็น `https://<โดเมน>/webhook` (ปิด "Auto-reply messages" ใน OA Manager)

## แก้ข้อมูลร้าน (`data/shop.json`)
- `products[]`: `name`, `aliases` (คำที่ลูกค้าใช้เรียก), `price`, `unit`, `bulk` (ไม่บังคับ), `inStock`
- `faq[]`: `keywords` (ลูกค้าพิมพ์คำใดคำหนึ่งก็ตรง), `label`, `answer`
- `greeting`, `fallback`, `handoff`, `quickReplies`
ข้อมูลในไฟล์เป็นตัวอย่าง ต้องแก้เป็นของร้านจริงก่อนใช้งาน

## อ่านสลิป

ลูกค้าส่งรูปสลิปมา บอทดูแค่ว่าเป็นสลิปหรือไม่ (ไม่อ่านยอดเงิน) แล้วตอบ "ขอบคุณค่ะ" — แอดมินตรวจยอดเอง
ไม่ตั้ง key = โหมดฟรี: ทุกรูปได้ "ขอบคุณค่ะ ได้รับรูปแล้ว" และแอดมินได้รับแจ้ง ถ้าอยากให้บอทแยกสลิปออกจากรูปอื่น ตั้ง `GEMINI_API_KEY` (แผนฟรีของ Google AI Studio) หรือ `ANTHROPIC_API_KEY` (คิดเงิน)
รูปที่ไม่ใช่สลิป / อ่านไม่ออก / ไฟล์อื่น → บอทไม่ตอบ แจ้งแอดมินทั้ง 3 คน

## ออเดอร์จากแชท (ร่างจากข้อความ LINE → หน้าจอพนักงาน)

ข้อความที่ลูกค้าพิมพ์ใน LINE OA กลายเป็นร่างออเดอร์ (`CH-0001`…) ที่พนักงานตรวจและยืนยันในหน้า **ออเดอร์จากแชท** ของหลังร้าน แล้วจึงเป็นคำสั่งซื้อ `NT-…` ที่ใช้ใบจัดของและ POS เดิมได้ · บอทไม่ตอบลูกค้าระหว่างเก็บรายการ และไม่ส่งอะไรให้ลูกค้าก่อนพนักงานยืนยัน

- เปิดด้วย Render: `CHATDRAFTS_MODE` (`off` · `pilot` · `on`), `CHATDRAFTS_SUPABASE_URL`, `CHATDRAFTS_SERVICE_ROLE_KEY` (แยกจาก `SUPABASE_*` ของแอป — ดูเหตุผลใน `docs/chat-to-order/01-analysis.md` ข้อ 9)
- OA อื่น: `/webhook/ch/<key>` ตามทะเบียน `line_channels`
- เอกสาร: `docs/chat-to-order/` — `01-analysis.md` (ระบบเดิมและสิ่งที่ต้องแก้) · `02-design-and-test.md` (ผลและการทดสอบ) · `03-enable-guide.md` (ขั้นเปิดใช้สำหรับเจ้าของ)
- ทดสอบ: `cd db && npm test` (ฐานข้อมูลและบอท) · `npm run test:ui` (เบราว์เซอร์ ต้องมี `NATTA_LIVE_DIR`)

## รายการสั่งจัดของที่ลูกค้าพิมพ์มาในแชท

ลูกค้า (เช่น โรงเรียน) พิมพ์รายการมาทีเดียวหลายบรรทัด เช่น
```
ไม้กวาดทางมะพร้าว=10
ไม้ถูพื้น=10
น้ำยาล้างห้องน้ำ=2แพค
```
บอทอ่านออกว่าเป็น "รายการสั่งจัดของ" แล้ว:
- **ส่งการ์ด "📋 มีรายการสั่งจัดของ — ไลน์ชื่อ …"** เข้า LINE แอดมินทุกคน มีรายการเป็นบรรทัดพร้อมจำนวน และปุ่ม "เปิดแชท" กับปุ่มเปิดหน้าหลังร้าน (`pickList.appUrl` = `https://admin.nattagroup.com/#projdocs` ไม่ใช่หน้าร้าน www)
- **เด้งแจ้งเตือนเข้ามือถือพนักงานที่ใช้แอปหลังร้าน** (Web Push ผ่าน `push-notify` ของแอป) — ทำงานเมื่อตั้ง `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` แล้วเท่านั้น
- **ข้อความต่อท้ายที่บอทตอบไม่ได้** ภายใน 10 นาที (เช่น "ประมาณวันที่ 28 ครูจะแวะมารับ") ส่งต่อให้แอดมินเป็นข้อความสั้น ๆ (ไม่เกิน 3 ข้อความต่อรายการ)
- **ลูกค้าไม่ได้คำตอบอะไร** และการ์ดเมนูของแอปไม่แทรก — ถ้าอยากให้บอทตอบว่า "รับรายการแล้ว" ใส่ประโยคที่ `pickList.reply`
- รายการเดียวกันส่งซ้ำภายใน 10 นาทีแจ้งครั้งเดียว · แจ้งถึงแอดมินแม้ลูกค้ากำลังคุยกับแอดมินอยู่ · push นับโควตา (ครั้งละ ~3 ข้อความ = ตามจำนวนแอดมิน)
- ปิดได้ที่ `data/shop.json` → `pickList.enabled: false` · ตั้งค่า: `maxLines` (บรรทัดที่โชว์ในการ์ด, 12), `followMinutes` (10), `appUrl` (เว้นว่างถ้าไม่ต้องการปุ่มแอป)

**อ่านรายการอย่างไร** — กติกาเดียวกับปุ่ม "📋 วางข้อความจาก LINE" ในหน้า "เอกสารโครงการ" ของแอปหลังร้าน (`src/picklist.js`): `ชื่อ=จำนวนหน่วย` · `ชื่อ:จำนวน` · `ชื่อ x จำนวน` · `ชื่อ 5 ด้าม` · `5 ด้าม ชื่อ` · ตัดเลขข้อ/เวลาแชท/คำลงท้าย (ครับ ค่ะ จ้า …) · บรรทัดอื่นเป็นหมายเหตุ · "วันที่ 28" = วันที่ต้องการ · หน่วยสะกดแบบลูกค้า (แพค แกลอน) ถูกแปลงเป็นแบบของร้าน (แพ็ค แกลลอน). เพื่อกันเข้าใจผิดว่าที่อยู่ ("บ้านเลขที่ 12 / หมู่ 5") หรือชื่อรุ่น ("Max 5 / Pro 3") เป็นออเดอร์ บอทต้องการ ≥ 2 รายการ และอย่างน้อยครึ่งหนึ่งต้องบอกจำนวนชัด (`=` `:` `x` หรือมีหน่วยนับ)

### สั่งทางแชท → ใบสั่งจัดในแอปหลังร้าน (`chatOrders`, ปิดไว้ก่อน)

เปิดแล้ว รายการที่ลูกค้าพิมพ์จะเข้าเป็น **งานใหม่ในแอปหลังร้านเอง** (ตาราง `project_docs` เดิมของหน้า "เอกสารโครงการ" เลข PJ-xxxx — ไม่มีระบบ/ตารางซ้ำ) ให้พนักงานตรวจแล้วออกใบสั่งจัดตามขั้นตอนเดิม

- **บอททำ**: สร้างงาน (สถานะ "ใหม่", `origin = 'chat'`) พร้อมรายการ ชื่อ/จำนวน/หน่วย · ผูกกับสินค้าในร้านเฉพาะที่ชัดเจนจริง (ชื่อตรงเป๊ะ หรือใกล้มากและไม่มีสินค้าอื่นใกล้เคียง — `chatOrders.match`) · ที่เหลือเก็บเป็น **ข้อความของลูกค้า ติดป้าย "รอตรวจสอบสินค้า"** พร้อมบอกสินค้าใกล้เคียงให้ · เก็บข้อความเดิมไว้ใน "บันทึกของร้าน" · ข้อความถัดมาของลูกค้าคนเดิมภายใน 30 นาที (`mergeMinutes`) ต่อเข้าใบเดิม (ถ้าพนักงานบันทึกใบนั้นไปแล้ว จะเปิดใบใหม่ ไม่เขียนทับ) · การ์ดแอดมินบอกเลขใบและปุ่ม "เปิดใบ PJ-xxxx ในแอป" (`https://admin.nattagroup.com/?doc=PJ-xxxx#projdocs`)
- **บอทไม่ทำ**: ไม่เพิ่ม/แก้สินค้า ไม่ใส่ราคา (ทุกบรรทัด `price = null` — พนักงานใส่เอง หรือกด "ใส่ราคาร้าน" ในแอป) ไม่ตัดสต็อก ไม่เปลี่ยนสถานะใบ ไม่ตอบลูกค้า
- **เปิดใช้** (ต้องตั้ง `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` บน Render ก่อน — ดู `/health` ช่อง `app` ต้องเป็น `on`) · **คู่มือทีละขั้น: [`CHAT-ORDERS-ENABLE.md`](CHAT-ORDERS-ENABLE.md)** · ตั้งที่ Render → Environment ได้เลยไม่ต้อง push โค้ด: `CHATORDERS_MODE` (`off`/`pilot`/`on`) · `CHATORDERS_ACK` (`on`/`off`) · `CHATORDERS_AI` (`off`/`pilot`/`on`) · `CHATORDERS_PILOT_IDS` (`Uxxx,Uyyy`) — ค่าที่ตั้งที่นี่ชนะไฟล์ `data/shop.json` → `chatOrders`
  - `"off"` (ค่าเริ่มต้น) = เหมือนเดิม แค่แจ้งแอดมิน
  - `"pilot"` = บันทึกเฉพาะ LINE ที่อยู่ใน `pilotUserIds` (ใส่ไอดีของตัวเองไว้ทดลองก่อน — ไอดีหาได้โดยพิมพ์ "ไอดีฉัน" ในแชท)
  - `"on"` = บันทึกให้ลูกค้าทุกคน
  - ดูสถานะที่ `/health` → `"orders": "off" | "pilot" | "on" | "no-db"` · แก้ไฟล์แล้วมีผลกับข้อความถัดไป ไม่ต้องรีสตาร์ท · **ย้อนกลับ = ตั้งเป็น `"off"`** (ใบที่สร้างไปแล้วอยู่ในแอป ลบ/ยกเลิกได้ที่หน้าเอกสารโครงการ)
- **แจ้งลูกค้าหลังพนักงานตรวจแล้ว** (`chatOrders.ack`, ปิดไว้): เมื่อพนักงานเลือกสถานะ "กำลังทำ" หรือ "เสร็จแล้ว" ในแอป บอทส่งประโยค `ack.text` ("ได้รับรายการสั่งซื้อแล้วค่ะ ร้านกำลังดำเนินการจัดสินค้า") ให้ลูกค้า **ครั้งเดียวต่อใบ** — ไม่ส่งถ้าลูกค้ากำลังคุยกับแอดมิน (ลูกค้ากดเลือกแอดมิน หรือแอปบันทึกว่ากำลังคุยกับแอดมิน — นานเท่าที่การ์ด "คุยกับแอดมิน" ของแอปเงียบ = `silence_hours` ปกติ 24 ชม. ปรับเฉพาะส่วนนี้ได้ที่ `ack.busyHours`) · ใบที่ยกเลิกไม่แจ้ง · นับโควตา push 1 ข้อความ/ใบ · ในโหมด `pilot` ส่งเฉพาะคนในรายการทดลอง
- **ให้ AI อ่านประโยคสั่งของ** (`chatOrders.ai.mode`, ปิดไว้): ข้อความเดียวที่เป็นประโยค เช่น "ขอสั่งไม้กวาด 10 อัน แล้วก็น้ำยาล้างจาน 2 แกลลอนนะคะ" กฎข้างบนอ่านไม่ได้ — เปิด `"pilot"`/`"on"` และตั้ง `GEMINI_API_KEY` (แผนฟรี) หรือ `ANTHROPIC_API_KEY` บน Render ได้ (`CHAT_AI_MODEL` เลือกรุ่น). ส่งไปให้ผู้ให้บริการ AI **เฉพาะตัวข้อความที่ดูเหมือนสั่งของ** (มีตัวเลข + หน่วย/คำสั่งซื้อ ไม่ใช่คำถามราคา) ไม่ส่งชื่อหรือไอดี LINE · AI แค่อ่าน: ชื่อสินค้าที่ไม่อยู่ในข้อความลูกค้า หรือจำนวนที่ลูกค้าไม่ได้เขียน จะถูกตัดทิ้ง · รายการที่ AI อ่านถูกติดป้ายและหมายเหตุ "แยกรายการด้วย AI" ให้พนักงานตรวจกับข้อความเดิมเสมอ
- **แอปหลังร้าน**: หน้า "เอกสารโครงการ" ถูกแพตช์ให้แสดงป้าย "สั่งทางแชท" / "รอตรวจสอบสินค้า" และเปิดใบจากลิงก์ได้ — ไฟล์แพตช์ วิธีย้อนกลับ และผลทดสอบอยู่ที่ [`app-patches/projdocs-chat-orders/`](app-patches/projdocs-chat-orders/README.md)
- ถ้าฐานข้อมูลล่ม/ช้า: แอดมินยังได้การ์ดตามเดิม (แต่ไม่มีเลขใบ) และลูกค้าไม่ถูกกระทบ — บอทรอฐานข้อมูลไม่เกิน ~12 วินาทีต่อข้อความ

## ข้อความที่บอทไม่เข้าใจ

บอทตอบสั้น ๆ ว่า "รับเรื่องแล้วค่ะ แอดมินจะตอบกลับในแชทนี้นะคะ" (ตั้งที่ `contact.receivedNote` — เว้นว่างถ้าอยากให้เงียบ) พร้อมปุ่มหัวข้อด้านล่าง และแจ้งแอดมินทั้ง 3 คน

โหมดไม่เสียเงิน: `contact.notify:false` (ไม่ push หาแอดมิน ใช้แจ้งเตือนของแอป OA) และ `contact.askOnUnknown:true` (ข้อความที่ไม่เข้าใจ → ตอบการ์ดถามว่าจะคุยกับใคร; ทักครั้งแรกก็ถามเช่นกัน; กดชื่อแอดมินแล้วบอทเงียบ)

**แจ้งเตือนแอดมิน (push)** ส่งเฉพาะ: ลูกค้าสั่งงาน/สั่งของ (คำใน `contact.orderWords`), ส่งสลิป/รูป, และเมื่อลูกค้ากดชื่อแอดมิน ข้อความที่บอทไม่เข้าใจ: เงียบ ไม่แจ้ง (`contact.askOnUnknown:false`)

## ถามว่าจะคุยกับใคร (ต่อการทักแต่ละครั้ง)

ลูกค้าคนหนึ่งนับเป็น "การทักหนึ่งครั้ง" (visit) เมื่อส่งข้อความครั้งแรกของวัน (เวลาไทย) หรือหายไปเกิน `contact.sessionGapHours` ชั่วโมง (ตอนนี้ 4) แล้วทักมาอีก
- **ทักสวัสดีล้วน ๆ** (เช่น "สวัสดีค่ะ", "hello") เป็นข้อความแรกของ visit → บอทส่งการ์ด "ต้องการติดต่อใครคะ" ให้เลือกแอดมินเลย (แทนการ์ดเมนู) พร้อมปุ่มหัวข้อด้านล่าง ส่งไม่เกินหนึ่งครั้งต่อ visit
- สวัสดีครั้งต่อไปใน visit เดิม → การ์ดเมนูตามปกติ; พิมพ์ "เมนู" ได้เมนูเสมอ
- **ข้อความที่บอทไม่เข้าใจ → เงียบเสมอ แม้เป็นข้อความแรกของวัน** (มักเป็นการตอบแอดมินที่กำลังคุยกับลูกค้าอยู่ — LINE ไม่บอกบอทว่าแอดมินตอบไปแล้ว)
- ถามเรื่องที่บอทตอบได้ (เช่น เวลาเปิดร้าน) → ตอบตามปกติ
- ลูกค้ากดเลือกชื่อแล้ว → ไม่ถามซ้ำใน visit นั้น
- ปิดได้ด้วย `contact.sessionAsk: false` (บอทรีสตาร์ทแล้วจะถามลูกค้าที่กลับมาอีกครั้งหนึ่งครั้ง เพราะจำไว้ในหน่วยความจำ)

## ข้อความที่ส่งติดกัน

LINE อาจส่งข้อความหลายบรรทัดของลูกค้ามาใน webhook ครั้งเดียว บอทจึงประมวลผลทีละข้อความต่อลูกค้าหนึ่งคนตามลำดับ (`src/serial.js`) แล้วตอบแค่ครั้งเดียว ข้อความที่ตามมาภายใน `contact.burstSeconds` (6) วินาทีหลังบอทตอบจะถูกข้าม

## แจ้งเตือนแอดมิน ไม่เกิน 1 ครั้งต่อลูกค้าต่อ 5 ชั่วโมง

การ์ดแจ้งเตือนแอดมิน (push นับโควตา OA) ส่งไม่เกิน 1 ครั้งต่อลูกค้าหนึ่งคนต่อ `contact.alertEveryHours` ชั่วโมง (ตอนนี้ 5) ไม่ว่าลูกค้าจะส่งรูป/สลิปมากี่ครั้ง และลูกค้ากดชื่อแอดมินคนเดิมซ้ำก็ไม่แจ้งซ้ำ (กดแอดมินคนอื่นแจ้งคนนั้น)
การตอบ "ขอบคุณค่ะ ได้รับรูปแล้ว" ฟรี (ไม่นับโควตา) จึงยังตอบได้ แต่รูปที่ส่งติดกันได้คำตอบเดียวต่อ `contact.pictureReplyMinutes` นาที (ตอนนี้ 10)

## เมนูถาวรใต้แชท (ริชเมนู)

**ริชเมนูที่ร้านใช้คือ "NATTA เมนูหลัก v1" ที่แอป NATTA GROUP สร้างไว้ใน LINE แล้ว** (1600×540, ข้อความบนแถบ "เมนูร้าน", 3 ช่อง: สั่งซื้อสินค้า → เปิดเว็บ www.nattagroup.com · ส่งเอกสารโครงการ · คุยกับแอดมิน — สองช่องหลังส่งข้อความธรรมดา บอทตอบเหมือนลูกค้าพิมพ์เอง). เมนูที่สร้างผ่าน API จะไม่ขึ้นให้ลูกค้าจนกว่าจะ**ตั้งเป็นเมนูของทุกคน** (`POST /v2/bot/user/all/richmenu/{richMenuId}`; เอาออก = `DELETE /v2/bot/user/all/richmenu`; ดูว่าตั้งอยู่ไหม = `GET /v2/bot/user/all/richmenu` ได้ 404 แปลว่ายังไม่ตั้ง) และ OA Manager ไม่แสดงเมนูที่สร้างผ่าน API จึงเปิด/ปิดจากหน้านั้นไม่ได้
- ปุ่ม "คุยกับแอดมิน" ได้การ์ดเลือกแอดมินเสมอ: ถ้าเปิด `admin_pick` ของแอปก็เป็นการ์ดของแอป (เงียบ 24 ชม.) ถ้ายังปิดอยู่บอทนี้ตอบการ์ด "ต้องการติดต่อใครคะ" เอง (`contact.buttonAliases` = คำที่นับเท่ากับ "ติดต่อแอดมิน")

ตัวติดตั้งในบอทนี้ (ด้านล่าง) เป็นทางเลือก ไว้ทำเมนูของบอทเองด้วยรูป `assets/richmenu.png` (2500×843) ใช้เฉพาะเมื่อไม่ได้ใช้เมนูของแอป:
- ช่องในเมนูตั้งเป็นลิงก์เว็บได้ด้วย `{ "label": "สั่งซื้อสินค้า", "uri": "https://…" }` (ต้อง https) นอกเหนือจากช่องที่ส่งข้อความ (`text`)
- **ปิดไว้ก่อน (`richMenu.enabled: false`)** เพื่อกันไม่ให้ไปทับเมนูของระบบอื่นที่ร้านใช้อยู่ (เช่น เมนูของแอป NATTA GROUP ข้างบน) — ถ้าเปิดแล้วมีเมนูอื่นตั้งเป็นของทุกคนอยู่ บอทจะไม่ทับ เว้นแต่พิมพ์ "ติดตั้งเมนู ทับ"
- **ติดตั้ง:** แอดมินพิมพ์ **"ติดตั้งเมนู"** ในแชทกับ OA (ต้องเป็นบัญชีแอดมินของร้าน) — บอทอัปโหลดรูปและตั้งเป็นเมนูของทุกคนเอง แล้วบอกผลกลับ ถ้ามีเมนูอื่นที่ระบบอื่นตั้งไว้ผ่าน API บอทจะไม่ทับ เว้นแต่พิมพ์ **"ติดตั้งเมนู ทับ"**
- **เอาออก:** พิมพ์ **"ลบเมนู"** (ลบเฉพาะเมนูที่บอทนี้สร้าง ชื่อ `richMenu.name` — ไม่แตะเมนูอื่นของ OA)
- ปุ่มแต่ละช่องตั้งที่ `richMenu.areas` (ข้อความที่ปุ่มส่งเป็นข้อความของลูกค้า บอทตอบเหมือนลูกค้าพิมพ์เอง): สั่งซื้อสินค้า → "สั่งของ", ส่งเอกสารโครงการ → การ์ดให้ส่งไฟล์และเลือกแอดมิน (`contact.documentAsk`), คุยกับแอดมิน → "ติดต่อแอดมิน"
- เปลี่ยนรูป: แทนที่ `assets/richmenu.png` (ต้อง PNG/JPEG ขนาด 2500×843 ไม่เกิน 1 MB) แล้วพิมพ์ "ติดตั้งเมนู" ใหม่ (เมนูเก่าชื่อเดียวกันจะถูกแทนที่)
- ข้อจำกัดของ LINE: ริชเมนูกับแป้นพิมพ์ใช้พื้นที่เดียวกัน กดช่องพิมพ์แล้วเมนูจะหุบ กดไอคอนเมนูมุมซ้ายล่างเพื่อเปิดกลับ; แสดงเฉพาะในแอปมือถือ
- การแตะปุ่มเมนู/ปุ่มหัวข้อคนละปุ่มติดกันไม่ถูกตัดตามกติกา "ตอบครั้งเดียว" และปลุกบอทได้แม้อยู่ในช่วงเงียบหลังเลือกแอดมิน
- ลูกค้าส่งไฟล์ (PDF ฯลฯ) → บอทตอบ "ได้รับไฟล์แล้ว" และแจ้งแอดมิน (ไม่เกิน 1 ครั้งต่อลูกค้าต่อ 5 ชั่วโมง) บอทไม่อ่านไฟล์

## การ์ดต้อนรับตอนเพิ่มเพื่อน

บอทส่งการ์ดต้อนรับเมื่อมีคนเพิ่มเพื่อน ถ้าใน OA Manager เปิด "ข้อความต้อนรับ" ไว้ด้วย ลูกค้าจะได้สองอัน — เลือกอันเดียว: ปิดของบอทด้วย `"welcome": false` ใน `data/shop.json` หรือปิดข้อความต้อนรับใน OA Manager
