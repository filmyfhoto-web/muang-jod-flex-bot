# หน้าแชตและออเดอร์ (รุ่น 18) — ไฟล์พร้อมติดตั้ง ยังไม่ได้ติดตั้งในระบบจริง

`../saleorders.module.js` คือรุ่น 18 แล้ว · `../saleorders.module.v17.js` คือรุ่น 17 · `../saleorders.module.v16.js` คือรุ่น 16 (แช่แข็งไว้ย้อนกลับได้)

## สิ่งที่เปลี่ยนจากรุ่น 16

รุ่น 17 (ตอบในแอปให้ขึ้นเร็วขึ้น):
- ข้อความที่ตอบลูกค้าทาง LINE ขึ้นในแชตทันที ในสถานะ "รอส่งทาง LINE…" โดยไม่ต้องรอเซิร์ฟเวอร์ตอบก่อน (เดิมต้องรอเซิร์ฟเวอร์ตอบและอ่านประวัติใหม่ก่อน ข้อความจึงขึ้นช้า)
- เมื่อเซิร์ฟเวอร์รับข้อความแล้ว ข้อความชั่วคราวจะถูกแทนด้วยข้อความจริง ไม่มีข้อความซ้ำ
- ถ้าเซิร์ฟเวอร์ไม่รับข้อความ ข้อความชั่วคราวจะถูกเอาออก ข้อความยังอยู่ในช่องพิมพ์ และขึ้นเหตุผล
- ผลการส่งขึ้นเร็วขึ้นหนึ่งจังหวะ (ตรวจแชตที่เปิดอยู่พร้อมรายชื่อ ไม่ต่อคิวกันทีละขั้น)
- กฎเดิมยังอยู่: "ส่งถึง LINE แล้ว" ขึ้นก็ต่อเมื่อบอทแจ้งว่า LINE รับข้อความแล้วเท่านั้น

รุ่น 18 (ใช้บนมือถือได้ง่ายขึ้น และรายการจากแชตครบขึ้น):
- บนมือถือ เมื่อคีย์บอร์ดขึ้น หน้าแชตจะสูงเท่าพื้นที่ที่มองเห็นจริง ช่องพิมพ์จึงไม่ถูกคีย์บอร์ดบัง (เดิมอยู่ใต้คีย์บอร์ด มองไม่เห็นว่าพิมพ์อะไร) และระหว่างพิมพ์จะซ่อนแถบแท็บ ป้ายจัดหมวด และคำอธิบายไว้ก่อน กลับมาเองเมื่อคีย์บอร์ดลง
- บนมือถือ ชื่อลูกค้าในหัวแชตมีที่แสดง (เดิมถูกบีบจนมองไม่เห็น) ลิงก์ "ดูสรุปออเดอร์" ย้ายไปอยู่ในเมนูเฟือง (จัดการแชต) ไอคอนสถานะ LINE ในหัวแชตซ่อนไว้บนมือถือ แต่คำอธิบายใต้ช่องพิมพ์ยังบอกสถานะการส่งอยู่
- คำอธิบายใต้หัวแชตบอกปุ่มที่มีจริง: การตอบใน LINE OA Manager แล้วบันทึกเข้าแชต ใช้เมนูเฟือง "บันทึกคำตอบจาก OA Manager" (เดิมเขียนถึงปุ่มชื่อ "จาก OA Manager" ที่ไม่มีอยู่)
- บนมือถือ ช่องพิมพ์ใช้ตัวอักษรขนาด 16 จุด เพื่อให้ iPhone ไม่ซูมหน้าจอเข้าเมื่อแตะช่อง
- ตัวอ่านรายการจากแชตรับชื่อสินค้าที่ลงท้ายด้วยตัวเลข เช่น "แม็ก MAX HD-10 1อัน" · "โพสอิท 3*3 1 โหล" · "คลิปหนีบดำ No110 2กล่อง" ให้ตรงกับบอท (เดิมข้าม 4 บรรทัดของลูกค้า GUN ไปเป็นหมายเหตุ)
- เบอร์โทรที่ตามด้วยหน่วย (เช่น "081 234 5678 อัน") ไม่นับเป็นจำนวนสินค้า

ไม่เปลี่ยนข้อมูลใบสั่งงาน ไม่แก้บอท และไม่ส่งข้อความเข้า LINE เอง

## ขั้นตอนติดตั้ง (ทำเมื่อเจ้าของสั่งเท่านั้น · ใน SQL Editor ของโปรเจกต์ที่ใช้งานจริง)

ระบบจริงตอนนี้เป็นรุ่น 16 ต้องรันสองไฟล์ตามลำดับ:

1. ตรวจว่าเป็นรุ่น 16:
   `select md5(code) as md5, enabled, seq from app_modules where name = 'saleorders';`
   ต้องได้ `f1c2063ce020ce5c0b5dfadb216663b1`
2. รัน `../upgrade-v16-to-v17.sql` (ข้อความที่ขึ้น: `saleorders: now v17 …`) แล้วตรวจว่าได้ `b60f6d6eec1415f73f0648afa4e5adad`
3. รัน `../upgrade-v17-to-v18.sql` (ข้อความที่ขึ้น: `saleorders: now v18 …`)
4. ตรวจผล: `select md5(code) as md5, enabled, seq from app_modules where name = 'saleorders';`
   ต้องได้ `36b6167986ffb92063f0d0a90249a602`, enabled เป็น `true` และ seq เป็น `66`

ถ้าต้องย้อนกลับ รัน `../downgrade-v18-to-v17.sql` แล้วค่อย `../downgrade-v17-to-v16.sql` แต่ละไฟล์ทำงานเฉพาะเมื่อโค้ดตรงกับรุ่นที่คาดไว้ และไม่ทับโค้ดที่ถูกแก้ไขไว้

ทุกไฟล์ทำงานซ้ำได้ ไม่แก้โมดูลอื่น และไม่แก้ข้อมูลใบสั่งงาน

## ทดสอบ (ในเครื่องพัฒนา ไม่กระทบระบบจริง)

```
cd stationery-bot/db
node --test test/saleorders-module-sql.test.js   # 65/65
node --test test/sale-orders-page.ui.test.mjs    # 24/24
node --test test/sale-line-page.ui.test.mjs      # 13/13 (รวม "ขึ้นทันที" เมื่อเซิร์ฟเวอร์ตอบช้า 800 มิลลิวินาที และการทดสอบหน้าจอมือถือ 3 ข้อ)
```

การทดสอบคีย์บอร์ดมือถือเป็นการจำลองด้วย Chromium (ทำให้พื้นที่ที่มองเห็นเล็กลง) ยังไม่ได้ทดสอบบน iPhone จริง ต้องลองบนมือถือจริงหลังติดตั้ง
