# หน้า "แชตและออเดอร์" (โมดูล `saleorders` ของหลังร้าน)

ทำตามภาพตัวอย่างและคำสั่งของเจ้าของ (3 พ.ย. 2569) · **ติดตั้งและเปิดใช้ในหลังร้านจริงแล้ว 4 พ.ย. 2569** (เจ้าของอนุมัติ) — เมนู "แชตและออเดอร์" อยู่ต่อจาก "แชทขายสินค้า"

| ไฟล์ | คืออะไร |
|---|---|
| `saleorders.module.js` | โค้ดหน้า (ใส่ในตาราง `app_modules` แบบเดียวกับหน้าอื่นของหลังร้าน) |
| `make-sql.mjs` | สร้าง `apply.sql` / `reverse.sql` จากโค้ดหน้า (รันใหม่ทุกครั้งที่แก้โค้ด — เทสต์จะล้มถ้าลืม) |
| `apply.sql` | ติดตั้งหน้าเป็นแถวใหม่ **แบบปิดไว้** (`enabled = false`) · ไม่แตะโมดูลอื่น · รันซ้ำได้ |
| `reverse.sql` | ถอดหน้าออก (ถอดเฉพาะเมื่อโค้ดยังเป็นรุ่นที่ติดตั้ง — ตรวจ md5) |
| `../../db/migrations/002_sale_orders.sql` (+ `.reverse.sql`) | ตารางและฟังก์ชันของใบสั่งงาน (ต้องติดตั้งก่อนหน้า) |

## หน้าตาและการใช้งาน

- **คอมพิวเตอร์ 3 คอลัมน์** — ซ้าย "แชตลูกค้า" (ค้นหาชื่อ/ข้อความ/เลขออเดอร์ · แท็บ ทั้งหมด / รอตอบ / กำลังสั่งงาน / เสร็จแล้ว นับจากข้อมูลจริง · จำนวนยังไม่อ่าน) · กลาง "ห้องแชต" (ข้อความลูกค้า/ร้าน รูป ไฟล์ โน้ตภายใน ข้อความสำเร็จรูป แนบไฟล์) · ขวา "ใบสั่งงาน / คำสั่งซื้อ"
- **มือถือ** — แท็บบน "รายชื่อแชต / แชต / ออเดอร์" (มีจุดเตือนเมื่อมีแชตรอตอบ และเมื่อใบยังไม่ได้บันทึก) · รายการสินค้าเป็นการ์ด ไม่มีการเลื่อนข้าง
- **ใบสั่งงาน** — ประเภท "สั่งเพื่อจัดสินค้า" หรือ "สั่งเพื่อจัดทำเอกสาร" (เลือกตอนเปิดใบ เปลี่ยนไม่ได้หลังบันทึก) · ลูกค้า/โทร · เลขที่ `ORD-2569-00001` (ออกเมื่อบันทึก) · วันที่สั่ง · ราคา ปกติ/ราคาโรงเรียน · รายการ (สินค้าในระบบ สินค้าพิมพ์เอง งานบริการ — แก้/ลบได้) · หมายเหตุ · รวม / VAT / ยอดรวมทั้งสิ้น · การส่งมอบ (รับที่ร้าน/จัดส่ง) · กำหนดส่ง · ผู้รับผิดชอบ · สถานะงาน · สถานะการชำระเงิน (แยกกัน) · ไฟล์แนบ (สลิป/ไฟล์งาน) · ปุ่ม **บันทึกออเดอร์** และ **ส่งสรุปให้ลูกค้า**
- **ขั้นตอนตามที่เจ้าของกำหนด** — ลูกค้าทัก → รับรายละเอียด → **"สร้างรายการจากแชต"** (อ่านข้อความลูกค้า หรือวางข้อความจาก LINE OA ด้วยกติกาเดียวกับบอท — สำเนาตรงตัวของ `src/picklist.js` มีเทสต์เทียบผล → ผูกกับสินค้าในระบบเมื่อชื่อตรงสินค้าเดียว → พนักงานติ๊ก/แก้ก่อน ไม่บันทึกเอง) → ตรวจแก้รายการ/ราคา → บันทึก → ตรวจสรุปและผู้รับ → คัดลอกไปส่ง (ตั้ง "รอลูกค้ายืนยัน" ได้ในปุ่มเดียว) → กำลังทำ/จัดสินค้า → พร้อมส่ง → ส่งมอบแล้ว + บันทึกชำระ → ปิดออเดอร์
- **กันพลาด** — ย้ายแชต/สลับใบ/เปิดใบใหม่ขณะยังไม่บันทึก → ถามก่อน (ร่างถูกเก็บไว้กับแชตของมันจนปิดหน้า) · ปิดหน้าเว็บขณะยังไม่บันทึก → เบราว์เซอร์เตือน · ปิดออเดอร์ที่ยังไม่ส่งมอบหรือยังค้างชำระ → ต้องกดยืนยัน (บันทึกในประวัติ) · ยกเลิกต้องใส่เหตุผล · มีคนอื่นแก้ใบเดียวกันก่อน → ไม่ทับ บอกให้โหลดใหม่ · กดบันทึกซ้ำ/ส่งซ้ำ → ได้ใบเดียว

## อะไรเชื่อมจริง · อะไรยังไม่เชื่อม

| ส่วน | สถานะ |
|---|---|
| รายชื่อแชต ข้อความ ขั้นการขาย | **จริง** — ตาราง `sale_threads` / `sale_msgs` ที่มีอยู่แล้ว (ชุดเดียวกับหน้า "แชทขายสินค้า" เดิม ซึ่งยังอยู่ครบ) · ตอนนี้ยังไม่มีแชตในตาราง (0 แถว) |
| ลูกค้า สินค้า ราคา ราคาโรงเรียน VAT | **จริง** — `customers` / `products` / สูตรราคาโรงเรียนเดิม `_school_item_price` (แบบเดียวกับหน้าสั่งของโรงเรียน: `markup_pct` / `round_to` / `price_special`) / `stores.vat_rate` (คัลเลอร์แล็ป 7% · การพิมพ์ ไม่มี VAT) — VAT คิดแยกนอกแบบเอกสารเดิมของร้าน |
| บันทึกใบสั่งงาน ยอดเงิน สถานะ ประวัติ | **จริง** (ติดตั้ง 002 แล้ว) — ฟังก์ชัน `sale_order_save` คิดยอดใหม่ฝั่งเซิร์ฟเวอร์ทุกครั้ง |
| ไฟล์แนบ/รูปในแชต | **จริง** — bucket ส่วนตัวใหม่ `sale-order-files` (002 สร้างให้ · เพดาน 10 MB เฉพาะรูป/PDF ตรวจโดย Storage เอง · พนักงานอ่าน/อัปโหลดได้ ลบหรือแก้ไม่ได้) · **ไม่แตะ** bucket `sale-files` ที่หน้า POS ใช้แนบไฟล์ |
| ข้อความจากลูกค้าใน LINE OA เข้าหน้านี้ | **ยังไม่ได้เชื่อมต่อ** — บอทรับข้อความ LINE อยู่ แต่ยังไม่เขียนลงแชตของหน้านี้ |
| ส่งข้อความ/สรุปจากหน้านี้ถึงลูกค้า (LINE / Facebook) | **ยังไม่ได้เชื่อมต่อ** — หน้าบอกตรง ๆ ทุกที่ · ใช้ "คัดลอกข้อความไปส่งเอง" หรือ "บันทึกสรุปลงแชตในระบบ" (ระบบบันทึกว่าคัดลอก/บันทึก ไม่ใช่ "ส่งแล้ว") · ไม่มีข้อความใดในหน้าที่บอกว่าส่งสำเร็จ |

## สิ่งที่หน้านี้ไม่ทำ (ตามคำสั่ง)
ไม่แตะ `orders` (คำสั่งซื้อจัดสินค้า) · `doc_orders` / `project_docs` (คำสั่งซื้อจัดทำเอกสาร) · `sales` (POS) · ไม่ตัดสต็อก · ไม่ออกเอกสาร · ไม่สร้างหรือผูกแถวในระบบอื่น · ไม่แก้สินค้า/ร้าน/โรงเรียน/ลูกค้า — มีเทสต์ตรวจทั้งหมดนี้

## ติดตั้ง — ทำแล้ว 4 พ.ย. 2569 (หลังเจ้าของอนุมัติ)
ลำดับที่ทำกับโปรเจกต์จริง (`mamlmgixovlwnjstetkj`) — ไฟล์จากคอมมิต `77fc00b` ดึงจาก GitHub เข้าฐานข้อมูลโดยตรงและตรวจ md5 ตรงกับไฟล์ในรีโพก่อนรันทุกครั้ง (ไม่ได้พิมพ์ซ้ำด้วยมือ):
1. **ซ้อมก่อน** — รัน `002_sale_orders.sql` จริงในธุรกรรมที่ย้อนกลับเสมอ แล้วลองบันทึกใบทดสอบด้วยสิทธิ์พนักงาน (ยอดตัวอย่างของเจ้าของ 2,750 + VAT 7% = 2,942.50 ถูก · ส่ง token เดิมซ้ำ → ได้ใบเดิม) และด้วยสิทธิ์ผู้เยี่ยมชม (ถูกปฏิเสธทั้งบันทึก/อ่านใบ/อ่านแชต) · ไม่มีอะไรค้างในฐานข้อมูล
2. **ติดตั้งจริง** `db/migrations/002_sale_orders.sql` (บันทึกใน migration history ชื่อ `sale_orders_002_chat_orders_page`) — ตาราง `sale_orders` `sale_order_items` `sale_order_events` `sale_order_years` + ฟังก์ชัน 4 ตัว + bucket ใหม่ `sale-order-files` กับนโยบายอ่าน/อัปโหลด
3. **เทียบก่อน-หลัง** — ลายนิ้วมือของทุกอย่างที่มีอยู่เดิมไม่เปลี่ยน: โมดูล 37 ตัว (โค้ด/seq/สถานะเปิด) · ทุกฟังก์ชันใน public · ทุกคอลัมน์ · ทุกนโยบายสิทธิ์ (public + storage) · ทุก bucket (รวม `sale-files` ของ POS) · จำนวนแถว: คำสั่งซื้อ 134 · รายการสินค้าในคำสั่งซื้อ 1,205 · สินค้า 861 · เอกสาร 81 · งานโครงการ 32 · POS 43 · ลูกค้า 254 · โรงเรียน 33 · ผลรวมสต็อก 120,656 · ไฟล์ใน Storage 1,360 · แชต 0
4. **ติดตั้งหน้า** `apply.sql` แบบปิดไว้ → โค้ดในฐานข้อมูล md5 `9559832b…` ตรงกับ `saleorders.module.js` ในรีโพ
5. **ตรวจผ่าน API จริง** — ผู้เยี่ยมชมเรียก `sale_order_save` / อ่าน `sale_orders` / อ่าน `sale_threads` → HTTP 401 permission denied ทั้งสาม (ฟังก์ชันใหม่ PostgREST มองเห็นแล้ว)
6. **เปิดหน้า** `update app_modules set enabled = true where name = 'saleorders'` → เมนู "แชตและออเดอร์" ขึ้นต่อจาก "แชทขายสินค้า" เมื่อพนักงานโหลดหลังร้านใหม่

**ผลกับระบบจริง:** ไม่มีการแก้/ลบข้อมูลเดิมแม้แต่แถวเดียว · ไม่มีการแก้ตาราง ฟังก์ชัน นโยบายสิทธิ์ หรือโมดูลเดิม · ไม่แตะ bucket `sale-files` ของ POS · สิ่งที่เพิ่มคือตาราง ฟังก์ชัน bucket ใหม่ และนโยบายใหม่ของ bucket นั้น

**ซ่อนหน้าทันที (ไม่ลบอะไร):** `update app_modules set enabled = false where name = 'saleorders';` แล้วโหลดหลังร้านใหม่

**ย้อนกลับทั้งหมด:** ปิดหน้า → `reverse.sql` → `002_sale_orders.reverse.sql` (ลบใบสั่งงานที่สร้างจากหน้านี้ทั้งหมด — ใช้ก่อนมีข้อมูลจริง · แชตและข้อความอยู่ครบ) · bucket `sale-order-files` ไม่ถูกลบด้วย SQL (Supabase ไม่อนุญาต) — ถ้าต้องการให้ลบใน Dashboard → Storage เอง

**สิ่งที่ยังไม่ได้ตรวจกับของจริง:** หน้าตาบนหลังร้านจริงและบนโทรศัพท์จริง (ผมเข้าหน้าหลังร้านที่ล็อกอินจากที่นี่ไม่ได้ — ตรวจด้วยหลังร้านตัวแทนที่ใช้กติกาตัวแปรและตัวโหลดโมดูลเดียวกับของจริง) · การอัปโหลดไฟล์ผ่าน Storage จริง (ตรวจเพดานในฐานข้อมูลและนโยบายแล้ว แต่ยังไม่ได้ลองอัปจริง)

## สิทธิ์
ใช้ระบบล็อกอินเดิมของหลังร้าน: ตารางใหม่เปิด RLS แบบเดียวกับตารางอื่น (`staff_all` สำหรับพนักงานที่ล็อกอิน) · ฟังก์ชันใหม่เรียกได้เฉพาะพนักงานที่ล็อกอิน · ผู้ที่ไม่ได้ล็อกอิน (anon) อ่าน/บันทึก/เรียกฟังก์ชันไม่ได้เลย (เทสต์แล้ว รวมกรณีสิทธิ์ตั้งต้นแบบ Supabase)
