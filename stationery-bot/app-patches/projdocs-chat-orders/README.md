# แพตช์หน้า "เอกสารโครงการ" ของแอปหลังร้าน — รองรับออเดอร์ที่ลูกค้าพิมพ์ทางแชท

หน้าจอหลังร้านของ NATTA GROUP ไม่ได้อยู่ใน GitHub แต่เก็บเป็นโค้ดในตาราง `app_modules` ของ Supabase (แถว `name = 'projdocs'`)
แพตช์นี้แก้เฉพาะแถวนั้น **ไม่แตะโมดูลอื่น ไม่แตะฟังก์ชัน/ตาราง/webhook ใด ๆ**

**ติดตั้งในฐานข้อมูลจริงแล้วเมื่อ 26 ต.ค. 2569** (รุ่นเดิม md5 `2bcd6432…` → รุ่นใหม่ md5 `c201be4f…`) — ไม่เปลี่ยนอะไรกับใบที่มีอยู่แล้ว
เพราะทุกอย่างทำงานเฉพาะใบที่บอทสร้างจากแชท (`origin = 'chat'`) หรือเมื่อเปิดลิงก์ที่มี `?doc=`

## แพตช์ทำอะไร

| ที่ไหน | เดิม | หลังแพตช์ |
|---|---|---|
| การ์ดในกระดานเอกสาร | ใบจากแชทจะดูเหมือนครูส่งมา มี "0 ไฟล์" | ป้ายเขียว **สั่งทางแชท** · "สั่ง 26 ต.ค. · 12:00" · ไม่โชว์ "0 ไฟล์" |
| ป้ายสรุปรายการสินค้าในการ์ด | `สินค้า 3 รายการ · รอใส่ราคา` | ต่อท้าย **`· รอตรวจสอบสินค้า 2`** เมื่อมีรายการที่ติดธง `review` |
| รายการสินค้าในหน้าใบ | บรรทัดไม่มี product_id = "ครูพิมพ์เอง · ไม่มีในร้าน" | บรรทัดที่บอทติดธง = **⚠️ รอตรวจสอบสินค้า · ใกล้เคียง: …** · บรรทัดที่ผูกสินค้าแล้วโชว์ "ลูกค้าพิมพ์ “…”" และคำเตือนหน่วยไม่ตรง |
| ลิงก์จากการ์ด LINE | `…/#projdocs` เปิดแค่หน้ารายการ | `…/?doc=PJ-0123#projdocs` เปิดใบนั้นเลย (ครั้งเดียว แล้วเอา `?doc` ออกจากที่อยู่) |
| กด "บันทึก" ในใบจากแชท | เขียนทับทุกอย่างที่เปิดค้างอยู่ | ถ้าบอทเพิ่งต่อรายการเข้าใบนั้น (ลูกค้าส่งเพิ่ม) จะ**ไม่บันทึกทับ** ขึ้นข้อความให้ปิด-เปิดใหม่ก่อน · ใบอื่นทั้งหมดบันทึกเหมือนเดิม |

ไม่มีอะไรเปลี่ยนในใบที่ครูส่งหรือใบที่ร้านสร้างเอง (ทดสอบแล้ว: การ์ดของใบเดิมเหมือนเดิมทุกไบต์ และบันทึกเหมือนเดิม)

## ไฟล์

- `projdocs.diff` — ส่วนที่เปลี่ยนจริง (59 บรรทัด) อ่านตรวจได้
- `apply.sql` — ติดตั้ง (ติดตั้งซ้ำได้ ไม่ทำอะไรถ้าติดตั้งแล้ว · ถ้าโมดูลถูกแก้ต่างจากที่คาด จะไม่ทำอะไรเลยและบอกว่าจุดไหนไม่ตรง)
- `reverse.sql` — **ย้อนกลับ** ให้โมดูลกลับเป็นรุ่นเดิมทุกไบต์ (ใช้ได้แม้คนอื่นแก้ส่วนอื่นของโมดูลไปแล้ว)

รันใน Supabase → SQL Editor (โปรเจกต์ `mamlmgixovlwnjstetkj`) ผู้ใช้เปิดหน้าแอปใหม่ (รีเฟรช) จึงจะเห็นผล

## ที่ไม่ได้แก้ (ตั้งใจ)

- หน้า "งานลูกค้า" (โมดูล `jobs`) ยังเรียกใบจากแชทว่า "ครูส่งเอกสาร / ครูส่งเอกสารทาง LINE" — ถูกแค่ครึ่งเดียว แต่ไม่ได้แก้เพื่อไม่แตะโมดูลที่สอง · ใช้งานได้ตามปกติ
- ฟังก์ชันแจ้งเตือนมือถือ `push-notify` ของแอป: รับเฉพาะลิงก์ `/` หรือ `/#ชื่อหน้า` จึงเด้งแล้วเปิดหน้ารายการเอกสาร (เลขใบอยู่ในหัวข้อ) · ส่วนปุ่มในการ์ด LINE เปิดใบนั้นตรง ๆ ได้ด้วย `?doc=`
- ตรวจแล้วว่าตาราง `project_docs` มีทริกเกอร์เดียว (`project_docs_archive_ts` ตอนเก็บเข้า Drive) และไม่มีฟังก์ชัน/ทริกเกอร์ใดส่ง LINE หาลูกค้าเองเมื่อมีใบใหม่

## ถ้ามีคนเขียนทับโมดูล `projdocs` ทั้งก้อน

แพตช์จะหายไป (แอปยังใช้ได้ปกติ แค่ใบจากแชทจะหน้าตาเหมือนใบที่ครูส่ง และลิงก์ `?doc=` เปิดแค่หน้ารายการ) — รัน `apply.sql` อีกครั้งเพื่อติดตั้งใหม่
(ถ้ามีแชท Claude/ผู้ช่วยอื่นกำลังแก้โมดูลนี้ ให้บอกว่าโมดูลมีบล็อกหมายเหตุ `(EH 2026-10-26)` อยู่ด้านบน และอย่าเขียนทับด้วยสำเนาเก่า)

## วิธีทดสอบที่ทำไว้ก่อนติดตั้ง

1. สร้างหน้าแอปหลังร้านจริง (index.html + admin1-3.js จากเว็บจริง) ในเบราว์เซอร์ทดสอบ ต่อกับฐานข้อมูลจำลอง ใส่โมดูลรุ่นเดิมและรุ่นใหม่ แล้วเช็ก 26 ข้อ:
   การ์ดใบเดิมเหมือนเดิมทุกไบต์ · ป้าย/ป้ายสรุป/ป้ายรอตรวจสอบ · เปิดใบจาก `?doc=` · ลิงก์เสีย (ไม่พบเอกสาร) · บันทึกปกติ · บันทึกถูกปฏิเสธเมื่อบอทเพิ่งต่อรายการ ·
   ใบเดิมไม่ถูกกันการบันทึก · ไม่มี error ในหน้า
2. ทดสอบ `apply.sql` / `reverse.sql` บน PostgreSQL จริง (PGlite): ติดตั้ง → ได้โมดูลใหม่เป๊ะ · ติดตั้งซ้ำไม่เปลี่ยน · ย้อนกลับ → ได้โมดูลเดิมทุกไบต์ ·
   ใช้ได้กับโมดูลที่คนอื่นแก้ส่วนอื่น · ปฏิเสธและไม่แก้อะไรถ้าจุดที่ต้องแก้ถูกเปลี่ยนไป
3. ติดตั้งจริงด้วยคำสั่งแทนที่แบบมีเงื่อนไข (ต้องเป็นรุ่นเดิม md5 `2bcd6432…` และเวลาแก้ไขล่าสุดตรงเป๊ะ) แล้วตรวจ md5 หลังติดตั้ง = `c201be4f…`
