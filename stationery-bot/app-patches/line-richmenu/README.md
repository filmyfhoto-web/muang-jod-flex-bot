# ฟังก์ชัน Supabase `line-richmenu` (เวอร์ชัน 8 · 2 พ.ย. 2569)

ตั้งริชเมนูของ LINE OA "นัฐภรณ์ เชียงกลาง" จากฐานข้อมูล — โค้ดจริงอยู่ที่ Supabase (โปรเจกต์ `mamlmgixovlwnjstetkj`, `verify_jwt: false`)
ไฟล์ `index.ts` นี้คือสำเนาของที่ deploy อยู่ เก็บไว้ให้ตรวจ/สร้างใหม่ได้

- เรียกได้เฉพาะที่ส่ง `key` ตรงกับ `app_secrets.push_hook_key` · token ของ LINE (`app_secrets.line_channel_token`) อ่านในฟังก์ชันเท่านั้น ไม่เคยถูกส่งออก
- วิธีเรียกจาก SQL โดยไม่แสดงคีย์: `select net.http_post(url := '<…>/functions/v1/line-richmenu', body := jsonb_build_object('action','status','key',(select btrim(value) from public.app_secrets where key='push_hook_key')))` แล้วอ่านผลจาก `net._http_response`

| action | ทำอะไร |
|---|---|
| `status` | รายการเมนูทั้งหมดใน OA + เมนูที่ทุกคนเห็นอยู่ (อ่านอย่างเดียว) |
| `webhook` | ที่อยู่ webhook ของ OA + ข้อมูลบัญชี · `test:true` = ให้ LINE ลองยิงไปที่ webhook (events ว่าง ไม่มีข้อความถึงลูกค้า) · `test:true` + `url` = ลองยิงไปที่ที่อยู่นั้นแทน โดยไม่เปลี่ยนค่าที่ตั้งไว้ (อ่านอย่างเดียว) |
| `set_webhook` + `url` (+ `force`) | ตั้งที่อยู่ webhook ของ OA (LINE ตั้งได้ที่เดียว): ให้ LINE ลองยิงที่อยู่ใหม่ก่อน ไม่ผ่านจะไม่เปลี่ยน (`force:true` = ข้ามการทดสอบ) · เปลี่ยนเฉพาะที่อยู่ ไม่แตะสวิตช์ "ใช้ webhook" · รับเฉพาะ https ของ `nattagroup-y.onrender.com` (บอท Render: `/webhook`) และ `wa.botcake.io` (Botcake) · คืน `prev` = ที่อยู่เดิม — ย้อนกลับโดยเรียกอีกครั้งด้วย url นั้น |
| `validate` (+ `layout:'v4'` / `'v3'` / `'v2'` หรือ `menu`) | ให้ LINE ตรวจรูปแบบเมนู (ไม่สร้างอะไร) |
| `fetch_check` + `image_url` | ดึงรูปจาก `https://nattagroup-y.onrender.com/assets/…` แล้วบอกขนาด/SHA-256 (ไม่แตะ LINE) |
| `apply` (+ `image_url` + `sha`, `layout`, `default`) | สร้างเมนูใหม่ → อัปโหลดรูป → ตั้งเป็นเมนูของทุกคน · มี `image_url` = เมนู v2 (3 ช่อง 2500×843) · `layout:'v3'` = เหมือน v2 แต่ปุ่มที่ 1 เป็น postback (เปิดแป้นพิมพ์ทันที + ฟอง "ต้องการคุยกับแอดมิน") · `layout:'v4'` = เมนู 5 ปุ่ม 2 แถว (3 ปุ่มเดิมโดยปุ่มแรกเป็น postback แบบ v3 + "อุปกรณ์การเรียน" + "บริการงานพิมพ์") รูป PNG 2500×1301 (รูปต้องมีขนาดเท่ากับเมนูของ layout นั้น) · `default:false` = สร้างและอัปรูปแล้วแต่ยังไม่ตั้งเป็นของทุกคน (ใช้ `link` ให้คนทดลอง) · ไม่มี `image_url` = เมนู v1 กับรูปใน DB · คืน `prev` = เมนูที่ใช้อยู่ก่อนหน้า |
| `link` + `user` + `id` / `unlink` + `user` | ให้ผู้ใช้คนเดียวเห็นเมนูนี้ (ไว้ทดลองก่อนเปลี่ยนให้ทุกคน) / เอาออก |
| `delete` + `id` | ลบเมนูที่ไม่ใช้แล้ว (ไม่ยอมลบเมนูที่ทุกคนเห็นอยู่) |
| `on` + `id` | ตั้งเมนูที่มีอยู่แล้วให้เป็นของทุกคน (ใช้ย้อนกลับ) |
| `off` | เลิกแสดงเมนูของทุกคน (ตัวเมนูยังอยู่) |
| `check` | ตรวจรูป v1 ที่เก็บใน `app_config.rm_menu_img` |

เมนูที่มีใน LINE ตอนเขียนไฟล์นี้:
- v1 `richmenu-f892d58d34f03a46834606e132c1a3dd` (เมนูเดิม 3 ช่อง)
- v2 `richmenu-c8a467b300a8cbc4320ad63fdf467d7f` (เมนูที่ลูกค้าเห็นอยู่ — 3 ช่องตามที่เจ้าของสั่ง; ปุ่มที่ 1 ส่งข้อความ "คุยกับแอดมิน")
- v3 `richmenu-eb6b1e2800e30fa073350c8fa763cee5` (ทดลอง — ปุ่มที่ 1 เป็น postback เปิดแป้นพิมพ์ทันที; ผูกกับ LINE ของเจ้าของร้านคนเดียวด้วย `link` ยังไม่เป็นของทุกคน)
- v4 (เมนู 5 ปุ่ม 2 แถว — เจ้าของสั่ง 2 พ.ย.; ปุ่มแรกเป็น postback แบบ v3) สร้างด้วย `apply` + `layout:'v4'` + `default:false` แล้ว `link` ให้เจ้าของทดลอง · id ดูจาก action `status` (ชื่อ "NATTA เมนูหลัก v4") · ถ้าเจ้าของโอเค → `on` + id ของ v4 แล้ว `unlink` ผู้ทดลอง; ย้อนกลับ = `on` + id ของ v2

ขั้นต่อไปของ v3: ถ้าเจ้าของลองบนมือถือแล้วฟองข้อความขึ้นถูกต้อง → `on` + id ของ v3 แล้ว `unlink` ผู้ทดลอง · ถ้าฟองไม่ขึ้น → เปลี่ยนเป็น `fillInText` (เติมคำว่า "คุยกับแอดมิน " ในช่องพิมพ์) แล้วทดลองใหม่ · เก็บ v2/v1 ไว้ย้อนกลับ
ปุ่ม postback ต้องมีบอท Render เป็นผู้รับ webhook ของ OA (บอทแปลง postback `talk-admin` เป็นคำว่า "คุยกับแอดมิน" — `src/postback.js`) — ดู action `webhook` ว่าตอนนี้ชี้ที่ไหน (เปลี่ยนได้ด้วย `set_webhook`)
