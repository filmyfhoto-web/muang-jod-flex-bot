# หน้า "กดสั่งสินค้าเพื่อออกเอกสาร" (ปุ่มที่ 3 ของริชเมนู)

เจ้าของร้านสั่ง (1 พ.ย. 2569): กดปุ่ม "กดสั่งสินค้าเพื่อออกเอกสาร" แล้วให้ขึ้นหน้าที่มี **ชื่อไลน์ · ชื่อโครงการ · งบประมาณ ·
รายการสินค้าเป็นช่องเลือก** หน้าตาเป็นตารางเหมือนใบเสร็จ/ใบส่งของ

ระบบเดิมมีหน้า **`https://www.nattagroup.com/pj.html`** ("ส่งเอกสารโครงการ", ทำเมื่อ 13–14 ต.ค.) อยู่แล้ว: ล็อกอิน LINE ด้วย LIFF ของร้าน →
ข้อมูลครู → โครงการ → รายการสินค้า → แนบไฟล์ → ส่งเข้าหลังร้าน (`project_docs`, เลข `PJ-…`) ผ่านฟังก์ชัน Supabase `doc-submit`
แพตช์นี้ **ต่อยอดหน้าเดิม ไม่เปลี่ยนฝั่งหลังบ้านเลย** (ไม่แตะฐานข้อมูล ฟังก์ชัน หรือสัญญาของ `doc-submit`)

> ไฟล์เว็บร้านไม่ได้อยู่ใน GitHub (deploy ขึ้น Vercel โปรเจกต์ `natta-shop` ด้วย CLI/API) จึงเก็บแพตช์ไว้ที่นี่ให้ตรวจ แบบเดียวกับ `app-patches/`

## หน้าเดิมกับหน้าใหม่

| | หน้าเดิม | หน้าใหม่ |
|---|---|---|
| ชื่อไลน์ | ใช้เป็นชื่อครูในช่องกรอก ไม่ได้โชว์เป็นของตัวเอง | แถบ **"ชื่อไลน์ของคุณ"** บนสุด: รูปโปรไฟล์ + ชื่อไลน์ + สถานะ "✓ เป็นเพื่อนกับร้านแล้ว" (ถ้าเช็กสถานะเพื่อนไม่ได้ จะไม่โชว์สถานะ) |
| ผู้สั่ง | "ข้อมูลครู" (โรงเรียน · ชื่อ · เบอร์) | "ข้อมูลผู้สั่ง" ช่องเดิมทุกช่อง · จำค่าไว้ให้ครั้งต่อไปเหมือนเดิม |
| โครงการ | ชื่อ · วันที่ต้องการ · งบประมาณ | ชื่อ · **งบประมาณ** · วันที่ต้องการ (ไม่บังคับทั้งสองอย่าง) |
| เลือกสินค้า | ช่องค้นหา แล้วเลือกจากรายการที่เด้งขึ้น | ค้นหา **และ** แถบ **หมวดสินค้า** (แตะเลือกหมวด) · รายการสินค้ามีรูป/หน่วย/ปุ่ม **+** แตะเลือก · ขึ้น ✓ พร้อมจำนวนที่เลือกแล้ว · "ดูเพิ่ม" ทีละ 40 · ไม่มีในร้านพิมพ์ชื่อเองได้ (ร้านจะหาให้) |
| รายการที่เลือก | การ์ดซ้อนกัน | **ตารางแบบใบส่งของ**: `# · รายการ · จำนวน/หน่วย` มีปุ่ม − + และพิมพ์จำนวนเองได้ · แถวสรุป "รวม N รายการ · ราคา ร้านใส่ให้ภายหลัง" |
| หลังส่ง | เลขที่ PJ + สรุปข้อมูล | เลขที่ PJ + สรุป **และตารางรายการสินค้าที่สั่ง** (เหมือนใบสรุป) |
| ปุ่มส่ง | "ส่งเอกสารให้ร้าน" | เหมือนเดิม + บอกจำนวนรายการ "(5 รายการ)" |

**ไม่มีราคาในหน้านี้ (ตั้งใจ)** — ร้านใส่ราคาให้ในหลังร้านเอง เพราะราคาโรงเรียนไม่เท่ากัน (`items.price = null` เหมือนหน้าเดิม)

## ที่ไม่เปลี่ยน (สัญญากับ `doc-submit`)

`cfg` · `me` · `products` · `sign` · `submit` และรูปแบบข้อมูลที่ส่ง (`teacher`, `project`, `files`, `items[{id?, name, qty}]`) เหมือนเดิมทุกตัวอักษร
ส่งได้ทั้งแบบมีรายการสินค้าอย่างเดียว ไฟล์อย่างเดียว หรือทั้งสองอย่าง · โหมด "เพิ่มไฟล์ในใบเดิม" และ "เอกสารที่ส่งแล้ว" ยังอยู่

## ทดสอบที่ทำแล้ว

`NODE_PATH=$(npm root -g) node harness.cjs pj.html shots` — เปิดหน้าจริงใน Chromium (จอ 390 และ 320 px) โดยจำลอง LINE ล็อกอินกับ `doc-submit`:
กรอกครบ → เลือกสินค้า (ตามหมวด / ค้นหา / พิมพ์เอง) → เพิ่ม-ลดจำนวน → ส่ง แล้วตรวจข้อมูลที่ส่งออกไป (ชื่อไลน์ถูกใส่เป็นชื่อผู้สั่ง, `items` 5 บรรทัด
มี `id` เฉพาะสินค้าในร้าน, จำนวนที่พิมพ์ถูกส่งไป, ไม่ต้องมีไฟล์) · ไม่มี error ในหน้า · หน้าไม่เลื่อนซ้าย-ขวาที่ 320 px
**ยังไม่ได้ทดสอบกับของจริง**: LINE ล็อกอินจริง, รายการสินค้าจริง 700+ รายการ, โปรไฟล์/สถานะเพื่อนจริง — ต้องลองบนมือถือหลังขึ้นเว็บ

## ก่อนขึ้นจริง ต้องจัดการ 4 อย่าง (ตอนเขียนไฟล์นี้ยังไม่ได้ทำ)

1. **เว็บร้านต้องเปิดให้ลูกค้าเข้าได้** — ตอนตรวจ (1 พ.ย. 21:0x น.) โปรเจกต์ `natta-shop` ตั้ง Vercel Authentication เป็น "All Deployments"
   ทำให้ `www.nattagroup.com` ทุกหน้า (รวม `pj.html` และปุ่มสั่งซื้อสินค้า) เด้งไปหน้าล็อกอิน Vercel ลูกค้าเปิดไม่ได้ · ต้องเป็น Standard Protection หรือปิด
2. **เปิดสวิตช์หน้านี้** — `app_config.line_bot.docs` ตอนนี้ `false` (หน้าเดิมจะขึ้น "ยังไม่เปิดรับทางหน้านี้") ·
   `'trial'` = เฉพาะแอดมินใน `line_notify` ใช้ได้ (ป้าย "โหมดทดลอง") · ลบ/`true` = เปิดให้ทุกคน
3. **ขึ้นเว็บ** — แทนไฟล์ `pj.html` ที่รากของโปรเจกต์ `natta-shop` (หน้าเดิมคือ sha1 `d75faa36a8211296aeeba4915825b5a3597dced8`,
   deployment `dpl_7QUE3MZTtrh7UvT6ujoJEfk2kaz3`) · **มีแชท/ผู้ช่วยอื่นกำลัง deploy โปรเจกต์นี้อยู่** (หน้าแรก `index.html`, `hp.css`, `sf.css`, `dr.js`) —
   ให้ deploy จากชุดไฟล์ล่าสุดของโปรเจกต์ + ไฟล์นี้ ไม่ใช่จากชุดเก่า เพื่อไม่ทับงานของกันและกัน · ย้อนกลับ = promote deployment ก่อนหน้า
4. **เปลี่ยนปุ่มที่ 3 ของริชเมนู** ให้เปิดหน้านี้ (`uri` → `https://www.nattagroup.com/pj.html`) — ต้องสร้างเมนูใหม่ (เมนูแก้ช่องในที่เดิมไม่ได้)
   เก็บเมนูเดิมไว้ย้อนกลับ: v2 `richmenu-c8a467b300a8cbc4320ad63fdf467d7f` · v1 `richmenu-f892d58d34f03a46834606e132c1a3dd`
   (สั่งผ่านฟังก์ชัน `line-richmenu` action `on` + id) · ทำหลังข้อ 1–3 เท่านั้น ไม่งั้นลูกค้ากดแล้วเจอหน้าปิด

หมายเหตุ LIFF: หน้านี้ล็อกอินด้วย `liff.login({redirectUri: location.origin + location.pathname})` — Endpoint URL ของ LIFF ในคอนโซล LINE ต้องครอบ
`https://www.nattagroup.com/pj.html` (หน้าเดิมใช้ที่อยู่นี้อยู่แล้ว จึงไม่ต้องแก้ ถ้าไม่มีใครเปลี่ยน)
