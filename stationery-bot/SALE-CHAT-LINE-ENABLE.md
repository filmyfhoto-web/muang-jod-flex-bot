# เปิดใช้ "แชตและออเดอร์ ↔ LINE OA" (ข้อความลูกค้าเข้าหน้า · พนักงานตอบจากหน้า)

> **สถานะ: พัฒนาและทดสอบเสร็จแล้ว ยังไม่ได้ติดตั้งในระบบจริง** — ยังไม่มีขั้นไหนในเอกสารนี้ถูกทำกับฐานข้อมูลจริง Render หรือ LINE · บอทที่ทำงานอยู่ตอนนี้ (รุ่น `bdb8752`) ไม่เปลี่ยน · ทุกขั้นย้อนกลับได้ (ดูท้ายเอกสาร)
> ตัวสวิตช์หลักอยู่ที่ Render (`SALECHAT_MODE`) ปิดได้ทันทีโดยไม่ต้อง deploy

## สิ่งที่ระบบทำเมื่อเปิด

1. **ลูกค้าทักใน LINE OA → ข้อความเข้าหน้า "แชตและออเดอร์" เอง** เป็นแชตใหม่ (ชื่อ/รูปโปรไฟล์จาก LINE · ป้าย LINE) — ข้อความตัวอักษร รูป (เก็บในที่เก็บไฟล์ส่วนตัวของหน้า) · สติกเกอร์ ไฟล์ วิดีโอ เสียง ตำแหน่ง แสดงเป็นโน้ตสั้น ๆ ในแชต · ข้อความเดียวกันที่ LINE ส่งซ้ำเข้าครั้งเดียว · **บอทไม่ตอบลูกค้าเพิ่มจากเดิมแม้แต่ข้อความเดียว** (เทสต์เทียบคำตอบของบอทกับตอนไม่มีหน้า: เหมือนกันทุกตัวอักษร)
2. **พนักงานพิมพ์ตอบในหน้า → ส่งถึงลูกค้าทาง LINE** ผ่านบอท (นับ 1 ข้อความจากโควตา push ของแพ็กเกจ LINE ต่อ 1 คำตอบ) · ข้อความในแชตมีสถานะตามจริง: **รอส่ง** → **ส่งถึง LINE แล้ว** (ขึ้นได้ทางเดียวคือบอทแจ้งว่า LINE รับข้อความแล้ว) หรือ **ส่งไม่สำเร็จ: <เหตุผล>** (เช่น โควตาเต็ม · ลูกค้าบล็อก OA) มีปุ่ม "ส่งใหม่" · ค้างเกิน 30 นาทีโดยบอทไม่มาหยิบ = **ไม่ได้ส่ง** (ไม่ส่งคำตอบเก่าไปทีหลัง) · บอทหยุดกลางคัน = **ไม่ทราบว่าถึงหรือไม่** (ส่งซ้ำได้ ไม่ซ้ำกับของเดิม)
3. **ป้าย "LINE OA: …" บนหน้าจอมาจากสัญญาณชีพที่บอทเขียนเองทุกนาที** — เชื่อมต่อแล้ว / ทดลอง / ปิดการรับ-ส่ง / ขาดการติดต่อ (เงียบเกิน 3 นาที) / ยังไม่ได้เชื่อมต่อ (ไม่เคยมีสัญญาณ) · ไม่ใช่การสมมติ · Facebook ยังไม่ได้เชื่อมต่อ (เหมือนเดิม)
4. **ส่งสรุปใบสั่งงานทาง LINE** ได้จากปุ่ม "ส่งสรุปให้ลูกค้า" (เมื่อแชตนั้นมาจาก LINE และบอทเชื่อมต่ออยู่) · ผลการส่งบันทึกลงประวัติของใบโดยฐานข้อมูลเอง เมื่อได้ผลสุดท้ายแล้วเท่านั้น (ส่งถึง/ไม่สำเร็จ/ไม่ได้ส่ง) · แชตที่ไม่ได้มาจาก LINE ยังใช้ "คัดลอก" หรือ "บันทึกลงแชต" เหมือนเดิม
5. **หลังพนักงานตอบจากหน้า บอทเงียบสำหรับลูกค้ารายนั้น** (เหมือนตอนลูกค้าเลือกคุยกับแอดมิน — ลูกค้าพิมพ์ "เมนู" เพื่อเรียกบอทกลับ) กันบอทแทรกกลางบทสนทนา · ปิดได้: `SALECHAT_QUIET=off`
6. **หน้ารีเฟรชเอง** ทุก ~8 วินาที (2.5 วินาทีขณะมีข้อความรอผลการส่ง): ข้อความใหม่ แชตใหม่ ยอด "รอตอบ" สถานะบอท โดยไม่ดึงเคอร์เซอร์ออกจากช่องพิมพ์และไม่ดึงหน้าลงล่างถ้ากำลังเลื่อนอ่านข้อความเก่า

## ที่ยังไม่ทำ / ข้อจำกัด (บอกตรง ๆ)

- **คำตอบที่พิมพ์ใน LINE OA Manager และคำตอบอัตโนมัติของบอทไม่แสดงในหน้านี้** (LINE ไม่ส่งข้อความขาออกเหล่านั้นให้บอท) — หน้าจะแสดงเฉพาะข้อความของลูกค้ากับข้อความที่ส่งจากหน้านี้ มีบรรทัดบอกไว้ในแชต LINE ทุกแชต · แนะนำให้ตอบจากหน้านี้ที่เดียวหลังเปิดใช้
- **ส่งรูป/ไฟล์ถึงลูกค้าจากหน้านี้ยังไม่ได้** — แนบในแชต LINE จะเก็บเป็นโน้ตภายในและบอกชัด (ส่งเฉพาะข้อความตัวอักษรและสรุปใบ)
- **ยังไม่มีแจ้งเตือนพนักงานเมื่อมีข้อความใหม่** (เห็นเมื่อเปิดหน้า · ยอด "รอตอบ" · การ์ดแจ้งแอดมินเดิมของบอทยังทำงานตามเดิม) — เป็นงานต่อไปถ้าต้องการ
- รองรับ OA หลักช่องเดียว (`main`) · ลูกค้ากลุ่ม/ห้องแชตไม่เก็บ (เฉพาะแชตตัวต่อตัว)
- ถ้าฐานข้อมูลล่มขณะลูกค้าทัก บอทลองซ้ำ 3 ครั้ง (~20 วินาที) ถ้ายังไม่ได้ ข้อความจะไม่เข้าหน้า (ยังอยู่ใน LINE OA Manager) และมีบรรทัดใน log
- Render แพ็กเกจฟรีที่ "หลับ" เมื่อไม่มีคนใช้: ข้อความลูกค้าปลุกบอทเอง แต่คำตอบที่พนักงานพิมพ์ตอนบอทหลับต้องรอบอทตื่น (ไม่เกิน 30 นาที แล้วจะไม่ส่ง) และป้ายจะขึ้น "ขาดการติดต่อ" — ถ้าใช้จริงจังแนะนำแพ็กเกจที่ไม่หลับ
- เก็บข้อความ/รูปของลูกค้าไว้ในฐานข้อมูลของร้าน (พนักงานที่ล็อกอินเท่านั้นเห็น) — เป็นข้อมูลส่วนบุคคลของลูกค้า ควรตัดสินใจเรื่องการเก็บ/ลบตามนโยบายของร้าน (ตอนนี้ไม่มีการลบอัตโนมัติ)
- **สิทธิ์ใช้ระบบล็อกอินเดิม** (ผู้ที่ล็อกอินหลังร้าน = พนักงาน ตรวจฝั่งฐานข้อมูลด้วยสิทธิ์ `authenticated` แบบเดียวกับตารางอื่นของหลังร้าน) — ตอนนี้โปรเจกต์ Supabase มีบัญชีล็อกอิน 3 บัญชี เป็นอีเมลทั้งหมด (ตรวจ 4 พ.ย.) ไม่มีลูกค้าสมัคร · ถ้าวันหนึ่งเปิดให้ลูกค้าสมัครบัญชีในโปรเจกต์เดียวกัน ต้องเพิ่มรายชื่อพนักงานให้ทั้งตารางเดิมและฟังก์ชันของสะพานนี้
- หน้า "แชทขายสินค้า" เดิมใช้แชตชุดเดียวกัน: แชต LINE จะโผล่ในหน้านั้นด้วย แต่หน้านั้นไม่มีทางส่งถึงลูกค้า (ในหน้านั้นเขียนไว้ว่า "ยังไม่ส่งถึง LINE") — ข้อความที่พิมพ์ในหน้านั้นจะขึ้นในหน้านี้ว่า **"บันทึกในระบบ · ไม่ได้ส่งถึงลูกค้า"** · **แนะนำให้ซ่อนหน้าเดิมตอนเปิด LINE จริง** (`update app_modules set enabled = false where name = 'salechat'` · ไม่ลบข้อมูล) — รอคำสั่งเจ้าของ

## ขั้นตอนเปิดใช้ (ทำตามลำดับ · ผมทำให้ทุกขั้นที่แตะฐานข้อมูล/โค้ด หลังเจ้าของอนุมัติทีละขั้น)

### ขั้นที่ 1 — ฐานข้อมูล Supabase (โปรเจกต์ `mamlmgixovlwnjstetkj`)
1. ซ้อมในธุรกรรมที่ย้อนกลับเสมอ (ดึง `db/migrations/003_sale_line_bridge.sql` จาก GitHub ตรวจ md5 ตรงกับไฟล์ก่อนรัน) แล้วลองรับข้อความ/เข้าคิว/แจ้งผลด้วยสิทธิ์จริงของแต่ละบทบาท
2. ติดตั้งจริง `003_sale_line_bridge.sql` — **เพิ่มอย่างเดียว**: ตาราง `sale_line_status` `sale_line_links` `sale_line_msgs` `sale_line_out` + ฟังก์ชัน 8 ตัว · ไม่แก้ตาราง ฟังก์ชัน นโยบาย หรือ bucket เดิม · เทียบลายนิ้วมือก่อน-หลัง (โมดูล ฟังก์ชัน คอลัมน์ นโยบาย bucket จำนวนแถว สต็อก) เหมือนตอนติดตั้ง 002
3. อัปเกรดโค้ดหน้า `app-patches/sale-orders-page/upgrade.sql` (หน้ารุ่นเดิม md5 `9559832b…` → รุ่นต่อ LINE) — ทำเฉพาะเมื่อโค้ดในระบบตรงกับรุ่นเดิมทุกไบต์ · สถานะเปิด/ปิดและลำดับเมนูไม่เปลี่ยน · หลังขั้นนี้หน้ายังแสดง "LINE OA: ยังไม่ได้เชื่อมต่อ" เพราะบอทยังไม่ส่งสัญญาณ

### ขั้นที่ 2 — Deploy โค้ดบอทรุ่นใหม่ (Render ดีพลอยจากสาขานี้เองเมื่อ push โดยไม่มี `[skip render]`)
โค้ดใหม่ **ไม่ทำอะไร** จนกว่าจะตั้งรหัสฐานข้อมูลและ `SALECHAT_MODE` (ขั้นที่ 3) · `/health` ต้องได้ผลเหมือนเดิมทุกค่า (`"app":"off"`) และมี `build` ใหม่ · ถ้าผิดปกติ ย้อน Render → Deploys → รุ่น `bdb8752`

### ขั้นที่ 3 — ตั้งค่าบน Render (Environment) — **เจ้าของต้องทำเอง** เพราะเป็นรหัสลับ
| ชื่อตัวแปร | ค่า | หมายเหตุ |
|---|---|---|
| `SALECHAT_SUPABASE_URL` | `https://mamlmgixovlwnjstetkj.supabase.co` | ไม่ใช่ความลับ |
| `SALECHAT_SERVICE_ROLE_KEY` | service role key ของโปรเจกต์ | **ความลับ** ใส่ที่ Render โดยตรง **ห้ามส่งในแชต/ห้ามใส่ในโค้ด** |
| `SALECHAT_MODE` | `pilot` | ขั้นทดลอง (ดูขั้นที่ 4) |
| `SALECHAT_PILOT_IDS` | (ไม่ต้องใส่) | ค่าเริ่มต้นคือ LINE ของฟิล์มใน `data/shop.json` · เพิ่มคนได้: `Uxxx,Uyyy` · ดูไอดีตัวเองโดยพิมพ์ **ไอดีฉัน** ในแชต OA |

**อย่าตั้ง `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`** ถ้ายังไม่ต้องการเปิดฟีเจอร์ "แอป" (การ์ดออเดอร์ · เมนู · คุยกับแอดมิน) — สองตัวนั้นเปิดคำตอบอัตโนมัติของแอปให้ลูกค้าทุกคน (ดู `CHAT-ORDERS-ENABLE.md`) · ใช้ชุด `SALECHAT_` แยกเพื่อให้เปิดเฉพาะสะพานนี้
หลัง Render เริ่มใหม่ เปิด `https://nattagroup-y.onrender.com/health` ต้องได้ `"salechat":"pilot"` (ถ้าได้ `"no-db"` แปลว่ายังไม่มีรหัสฐานข้อมูล) · ภายใน 1 นาที ป้ายบนหน้าเปลี่ยนเป็น **"LINE OA: ทดลอง"**

### ขั้นที่ 4 — ทดลองกับ LINE ของฟิล์มเอง (โหมด pilot — ลูกค้าคนอื่นไม่ได้รับผลใด ๆ)
1. ส่งข้อความหา OA ร้านจาก LINE ส่วนตัว เช่น "ทดสอบ" · ส่งรูป · ส่งสติกเกอร์ → ในหน้า "แชตและออเดอร์" ต้องมีแชตใหม่ชื่อ LINE ของคุณ ภายใน ~10 วินาที พร้อมข้อความ รูป และโน้ตสติกเกอร์ · **ต้องไม่มี**ข้อความตอบกลับใหม่จากบอทเพิ่มจากที่เคยตอบ
2. พิมพ์ตอบจากหน้า → ข้อความขึ้น "รอส่งทาง LINE…" แล้วเป็น "ส่งถึง LINE แล้ว (LINE รับข้อความแล้ว)" และ LINE ของคุณต้องได้รับข้อความนั้นจริง (นับ 1 ข้อความจากโควตา — ดูเหลือโควตาในป้าย LINE OA ได้โดยเอาเมาส์ชี้ หรือพิมพ์ **โควตา** ในแชต OA)
3. ลูกค้าอื่นส่งข้อความเข้ามา → ไม่เข้าหน้า (ยังอยู่ใน LINE OA Manager) และบอทตอบเหมือนเดิม
4. ถ้ามีข้อใดไม่ตรง ตั้ง `SALECHAT_MODE=off` ทันที (บอทกลับเป็นเหมือนเดิม ไม่ต้อง deploy)

### ขั้นที่ 5 — ใช้จริงกับลูกค้าทุกคน (ต้องอนุมัติ)
`SALECHAT_MODE=on` ที่ Render (ไม่ต้อง deploy ใหม่) · ตัดสินใจเรื่องซ่อนหน้า "แชทขายสินค้า" เดิม (ดูข้อจำกัดข้างบน) และการเก็บข้อมูลลูกค้า

## ย้อนกลับ (ทำได้ทันที)

| ต้องการ | ทำอย่างไร |
|---|---|
| หยุดรับ/ส่งทันที | Render → Environment → `SALECHAT_MODE` = `off` (บอทกลับไปเหมือนเดิมทุกอย่าง · ข้อความที่ค้างในคิวจะไม่ถูกส่ง และขึ้นว่า "ไม่ได้ส่ง" หลัง 30 นาที) |
| หยุดไม่ให้บอทใช้ฐานข้อมูลเลย | ลบ `SALECHAT_SUPABASE_URL` / `SALECHAT_SERVICE_ROLE_KEY` ที่ Render |
| หน้ากลับเป็นรุ่นเดิม (ไม่มีส่วน LINE) | `app-patches/sale-orders-page/downgrade.sql` (ได้โค้ดรุ่นเดิมกลับมาตรงทุกไบต์ md5 `9559832b…`) |
| ถอดสะพานออกจากฐานข้อมูล | `db/migrations/003_sale_line_bridge.reverse.sql` — ลบตาราง/ฟังก์ชันของสะพาน · **ไม่ลบ**แชตและข้อความที่รับมาแล้ว (กลายเป็นแชตธรรมดา) · ตั้ง `SALECHAT_MODE=off` ก่อน |
| ถอยบอททั้งตัว | Render → Deploys → รุ่น `bdb8752` → Rollback |
