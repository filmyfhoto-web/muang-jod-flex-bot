# เปิดใช้ "แชตและออเดอร์ ↔ LINE OA" (ข้อความลูกค้าเข้าหน้า · พนักงานตอบจากหน้า)

> **สถานะ (4 พ.ย. 2569): ติดตั้งในระบบจริงแล้วส่วนที่ 1–3 · ยังรอส่วนที่ 4–5**
> 1. ตารางและฟังก์ชันของสะพาน LINE (migration 003) — ติดตั้งแล้ว
> 2. หน้า "แชตและออเดอร์" รุ่นล่าสุด (v3, รีเฟรชทุก 2 วินาที) — ติดตั้งแล้ว
> 3. หน้า "แชทขายสินค้า" เดิม — ซ่อนแล้ว (ตามคำตอบของเจ้าของ · ไม่ลบข้อมูล)
> 4. บอท Render รุ่นที่มีสะพาน — กำลังดีพลอยจากคอมมิตนี้ (ยังไม่รับหรือส่งข้อความจนกว่าจะตั้งโหมด)
> 5. คีย์ฐานข้อมูลและโหมดบน Render — **เจ้าของต้องตั้งเอง** (รหัสลับไม่ส่งในแชต)
>
> ยังไม่มีลูกค้าคนใดได้รับผลจากสะพาน จนกว่าจะตั้งโหมด `pilot` หรือ `on` · ตัวสวิตช์หลักอยู่ที่ Render (`SALECHAT_MODE`) ปิดได้ทันทีโดยไม่ต้อง deploy

## สิ่งที่ระบบทำเมื่อเปิด

1. **ลูกค้าทักใน LINE OA → ข้อความเข้าหน้า "แชตและออเดอร์" เอง** เป็นแชตใหม่ (ชื่อ/รูปโปรไฟล์จาก LINE · ป้าย LINE) — ข้อความตัวอักษร รูป (เก็บในที่เก็บไฟล์ส่วนตัวของหน้า) · สติกเกอร์ ไฟล์ วิดีโอ เสียง ตำแหน่ง แสดงเป็นโน้ตสั้น ๆ ในแชต · ข้อความเดียวกันที่ LINE ส่งซ้ำเข้าครั้งเดียว · **บอทไม่ตอบลูกค้าเพิ่มจากเดิม** (เทสต์เทียบคำตอบของบอทกับตอนไม่มีหน้า: เหมือนกัน)
2. **พนักงานพิมพ์ตอบในหน้า → ส่งถึงลูกค้าทาง LINE** ผ่านบอท (นับ 1 ข้อความจากโควตา push ของแพ็กเกจ LINE ต่อ 1 คำตอบ) · ข้อความในแชตมีสถานะตามจริง: **รอส่ง** → **ส่งถึง LINE แล้ว** (ขึ้นได้ทางเดียวคือบอทแจ้งว่า LINE รับข้อความแล้ว) หรือ **ส่งไม่สำเร็จ: <เหตุผล>** (เช่น โควตาเต็ม · ลูกค้าบล็อก OA) มีปุ่ม "ส่งใหม่" · ค้างเกิน 30 นาทีโดยบอทไม่มาหยิบ = **ไม่ได้ส่ง** (ไม่ส่งคำตอบเก่าไปทีหลัง) · บอทหยุดกลางคัน = **ไม่ทราบว่าถึงหรือไม่** (ส่งซ้ำได้ ไม่ซ้ำกับของเดิม)
3. **ป้าย "LINE OA: …" บนหน้าจอมาจากสัญญาณชีพที่บอทเขียนเองทุกนาที** — เชื่อมต่อแล้ว / ทดลอง / ปิดการรับ-ส่ง / ขาดการติดต่อ (เงียบเกิน 3 นาที) / ยังไม่ได้เชื่อมต่อ (ไม่เคยมีสัญญาณ) · ไม่ใช่การสมมติ · Facebook ยังไม่ได้เชื่อมต่อ (เหมือนเดิม)
4. **ส่งสรุปใบสั่งงานทาง LINE** ได้จากปุ่ม "ส่งสรุปให้ลูกค้า" (เมื่อแชตนั้นมาจาก LINE และบอทเชื่อมต่ออยู่) · ผลการส่งบันทึกลงประวัติของใบโดยฐานข้อมูลเอง เมื่อได้ผลสุดท้ายแล้วเท่านั้น · แชตที่ไม่ได้มาจาก LINE ยังใช้ "คัดลอก" หรือ "บันทึกลงแชต" เหมือนเดิม
5. **หลังพนักงานตอบจากหน้า บอทเงียบสำหรับลูกค้ารายนั้น** (เหมือนตอนลูกค้าเลือกคุยกับแอดมิน — ลูกค้าพิมพ์ "เมนู" เพื่อเรียกบอทกลับ) · ปิดได้: `SALECHAT_QUIET=off`
6. **ความเร็ว (ตามที่เลือก 4 พ.ย. "เร็วพอสำหรับงานขาย"):** บอทเช็กคิวส่งทุก 1 วินาที และหน้ารีเฟรชทุก 2 วินาที (1 วินาทีขณะมีข้อความรอผลการส่ง) → ข้อความที่พนักงานตอบไปถึง LINE ภายในราว 1–2 วินาที และข้อความใหม่ของลูกค้าขึ้นในหน้าภายในราว 2 วินาที (ค่าจริงขึ้นกับ LINE และเครือข่าย · LINE OA Manager ประมาณ 1 วินาที) · หน้าไม่ดึงเคอร์เซอร์ออกจากช่องพิมพ์ และไม่ดึงหน้าลงล่างถ้ากำลังเลื่อนอ่านข้อความเก่า

## ที่ยังไม่ทำ / ข้อจำกัด (บอกตรง ๆ)

- **คำตอบที่พิมพ์ใน LINE OA Manager และคำตอบอัตโนมัติของบอทไม่แสดงในหน้านี้** (LINE ไม่ส่งข้อความขาออกเหล่านั้นให้บอท) — หน้าจะแสดงเฉพาะข้อความของลูกค้ากับข้อความที่ส่งจากหน้านี้ มีบรรทัดบอกไว้ในแชต LINE ทุกแชต · แนะนำให้ตอบจากหน้านี้ที่เดียวหลังเปิดใช้
- **ส่งรูป/ไฟล์ถึงลูกค้าจากหน้านี้ยังไม่ได้** — แนบในแชต LINE จะเก็บเป็นโน้ตภายในและบอกชัด (ส่งเฉพาะข้อความตัวอักษรและสรุปใบ)
- **ยังไม่มีแจ้งเตือนพนักงานเมื่อมีข้อความใหม่** (เห็นเมื่อเปิดหน้า · ยอด "รอตอบ" · การ์ดแจ้งแอดมินเดิมของบอทยังทำงานตามเดิม) — เป็นงานต่อไปถ้าต้องการ
- รองรับ OA หลักช่องเดียว (`main`) · ลูกค้ากลุ่ม/ห้องแชตไม่เก็บ (เฉพาะแชตตัวต่อตัว)
- ถ้าฐานข้อมูลล่มขณะลูกค้าทัก บอทลองซ้ำ 3 ครั้ง (~20 วินาที) ถ้ายังไม่ได้ ข้อความจะไม่เข้าหน้า (ยังอยู่ใน LINE OA Manager) และมีบรรทัดใน log
- ถ้าบริการบอทบน Render หลับ คำตอบที่พนักงานพิมพ์ตอนนั้นต้องรอให้บอทตื่น (ไม่เกิน 30 นาที แล้วจะไม่ส่ง) และป้ายจะขึ้น "ขาดการติดต่อ" — ควรตรวจแพ็กเกจของบริการบอทว่าหลับได้หรือไม่ (ยังไม่ได้ตรวจ)
- เก็บข้อความ/รูปของลูกค้าไว้ในฐานข้อมูลของร้าน (พนักงานที่ล็อกอินเท่านั้นเห็น) — เป็นข้อมูลส่วนบุคคลของลูกค้า ควรตัดสินใจเรื่องการเก็บ/ลบตามนโยบายของร้าน (ตอนนี้ไม่มีการลบอัตโนมัติ)
- **สิทธิ์ใช้ระบบล็อกอินเดิม** (ผู้ที่ล็อกอินหลังร้าน = พนักงาน ตรวจฝั่งฐานข้อมูลด้วยสิทธิ์ `authenticated` แบบเดียวกับตารางอื่นของหลังร้าน) — ตอนนี้โปรเจกต์ Supabase มีบัญชีล็อกอิน 3 บัญชี เป็นอีเมลทั้งหมด (ตรวจ 4 พ.ย.) ไม่มีลูกค้าสมัคร · ถ้าวันหนึ่งเปิดให้ลูกค้าสมัครบัญชีในโปรเจกต์เดียวกัน ต้องเพิ่มรายชื่อพนักงานให้ทั้งตารางเดิมและฟังก์ชันของสะพานนี้
- **หน้า "แชทขายสินค้า" เดิม: ซ่อนแล้ว** (4 พ.ย. ตามคำตอบ "ซ่อนไว้") — ไม่ลบข้อมูล · กลับมาเปิดได้ด้วย `update app_modules set enabled = true where name = 'salechat';` (ถ้าเปิดกลับ แชต LINE จะโผล่ในหน้านั้นด้วย และข้อความที่พิมพ์ในหน้านั้นไม่ถึงลูกค้า)

## ขั้นตอนที่เหลือ (ทำตามลำดับ)

### ขั้นที่ 2 — บอทรุ่นที่มีสะพานขึ้น Render (กำลังทำ)
คอมมิตนี้ไม่มี `[skip render]` จึงดีพลอยอัตโนมัติ · บอทมีสะพานแต่ **ยังไม่รับหรือส่งข้อความ** จนกว่าจะตั้ง `SALECHAT_MODE` เป็น pilot หรือ on · ถ้ามีคีย์ฐานข้อมูลตั้งอยู่แล้ว (`SALECHAT_` / `CHATDRAFTS_` / `SUPABASE_`) บอทจะรายงานสัญญาณว่า "ปิด" ทุกนาทีอยู่แล้ว (ตารางมีแล้วตั้งแต่วันนี้) · `/health` ต้องได้ `"app":"off"` และ `build` ใหม่ (ไม่มี `"salechat"` จนกว่าจะตั้งโหมด) · ถ้าผิดปกติ ย้อน Render → Deploys → รุ่น `bdb8752`

### ขั้นที่ 3 — ตั้งค่าบน Render (Environment) — **เจ้าของต้องทำเอง** เพราะเป็นรหัสลับ
| ชื่อตัวแปร | ค่า | หมายเหตุ |
|---|---|---|
| `SALECHAT_SUPABASE_URL` | `https://mamlmgixovlwnjstetkj.supabase.co` | ไม่ใช่ความลับ |
| `SALECHAT_SERVICE_ROLE_KEY` | service role key ของโปรเจกต์ | **ความลับ** ใส่ที่ Render โดยตรง **ห้ามส่งในแชต/ห้ามใส่ในโค้ด** |
| `SALECHAT_MODE` | `pilot` | ขั้นทดลอง (ดูขั้นที่ 4) |
| `SALECHAT_PILOT_IDS` | (ไม่ต้องใส่) | ค่าเริ่มต้นคือ LINE ของฟิล์มใน `data/shop.json` · เพิ่มคนได้: `Uxxx,Uyyy` |

**อย่าตั้ง `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`** ถ้ายังไม่ต้องการเปิดฟีเจอร์ "แอป" (การ์ดออเดอร์ · เมนู · คุยกับแอดมิน) — สองตัวนั้นเปิดคำตอบอัตโนมัติของแอปให้ลูกค้าทุกคน (ดู `CHAT-ORDERS-ENABLE.md`) · ใช้ชุด `SALECHAT_` แยกเพื่อให้เปิดเฉพาะสะพานนี้
หลังตั้งและ Render เริ่มใหม่ เปิด `https://nattagroup-y.onrender.com/health` ต้องได้ `"salechat":"pilot"` (ถ้าได้ `"no-db"` แปลว่ายังไม่มีคีย์ที่ใช้ได้) · ภายในไม่กี่นาที ป้ายบนหน้าเปลี่ยนเป็น **"LINE OA: ทดลอง"**

### ขั้นที่ 4 — ทดลองกับ LINE ของฟิล์มเอง (โหมด pilot — ลูกค้าคนอื่นไม่ได้รับผลใด ๆ)
1. ส่งข้อความหา OA ร้านจาก LINE ส่วนตัว เช่น "ทดสอบ" · ส่งรูป · ส่งสติกเกอร์ → ในหน้า "แชตและออเดอร์" ต้องมีแชตใหม่ชื่อ LINE ของคุณ ภายใน ~5 วินาที พร้อมข้อความ รูป และโน้ตสติกเกอร์ · **ต้องไม่มี**ข้อความตอบกลับใหม่จากบอทเพิ่มจากที่เคยตอบ
2. พิมพ์ตอบจากหน้า → ข้อความขึ้น "รอส่งทาง LINE…" แล้วเป็น "ส่งถึง LINE แล้ว (LINE รับข้อความแล้ว)" ภายในไม่กี่วินาที และ LINE ของคุณต้องได้รับข้อความนั้นจริง (นับ 1 ข้อความจากโควตา — ดูโควตาได้ที่ป้าย LINE OA หรือพิมพ์ **โควตา** ในแชต OA)
3. ลูกค้าอื่นส่งข้อความเข้ามา → ไม่เข้าหน้า (ยังอยู่ใน LINE OA Manager) และบอทตอบเหมือนเดิม
4. ถ้ามีข้อใดไม่ตรง ตั้ง `SALECHAT_MODE=off` ทันที (บอทกลับเป็นเหมือนเดิม ไม่ต้อง deploy)

### ขั้นที่ 5 — ใช้จริงกับลูกค้าทุกคน (ต้องอนุมัติ)
`SALECHAT_MODE=on` ที่ Render (ไม่ต้อง deploy ใหม่) · และการเก็บข้อมูลลูกค้าตามนโยบายร้าน

- รอบนี้ไม่มีการแก้บอท การ์ดลูกค้าและการ์ดทีมงานยังเปิดตามเดิม

**สถานะ (8 พ.ย. 2569, เจ้าของส่งภาพอ้างอิง Pancake ซ้ำ — "ทำรูปแบบสีๆแบบนี้เพื่อสะดวกแล้วใช้งานง่ายๆ"):** หน้า "แชตและออเดอร์" รุ่น 12 ติดตั้งแล้ว (md5 `7fdbca68…` · เปิดใช้อยู่ · ลำดับเดิม 66 · ดึงจาก GitHub ที่คอมมิต `0dd90ff` และตรวจ md5 ก่อนรัน) — ไม่มีการเปลี่ยนฐานข้อมูล รอบนี้แก้แค่หน้าจอ:
- ป้ายสี 4 แบบ (สอบถาม/ปัญหา/ด่วน/ตอบกลับภายหลัง) จากเดิมซ่อนอยู่หลังปุ่ม "ป้าย ▾" ที่ต้องกดเปิดก่อน **เปลี่ยนเป็นแถว 4 ปุ่มสีโชว์อยู่ตลอดเวลา** เหนือแถวข้อความด่วน ตรงตำแหน่งเดียวกับภาพ Pancake ที่เจ้าของส่งมา
- กดปุ่มสีที่ยังไม่ติด = ติดป้ายนั้นทันที · กดปุ่มสีที่ติดอยู่แล้วซ้ำ = เอาป้ายออก (ไม่ต้องมีปุ่ม "ไม่มีป้าย" แยกต่างหากแล้ว)
- ปุ่มสถานะงานกับปุ่มผู้รับผิดชอบที่หัวแชตไม่เปลี่ยน ยังเป็นปุ่มกดเปิดเมนูแบบเดิม (เจ้าของถามถึงแค่เรื่องสีของป้าย)
- **ปิดช่องว่างการทดสอบจากรุ่น 10**: รอบที่แล้วป้ายสียังไม่มีเทสต์เบราว์เซอร์จริงโดยเฉพาะ รอบนี้เขียนเพิ่มแล้ว (กดติดป้าย/กดเอาออก/แถบสีที่รายการซ้าย) ทดสอบผ่านครบ
- รอบนี้ไม่มีการแก้บอท การ์ดลูกค้าและการ์ดทีมงานยังเปิดตามเดิม
