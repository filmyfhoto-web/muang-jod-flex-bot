# LINE OA Chat to Order — รายงานวิเคราะห์ระบบเดิมและสิ่งที่ต้องแก้

ตรวจเมื่อ 27 ต.ค. 2569 แบบ **อ่านอย่างเดียว** (ฐานข้อมูล Supabase `mamlmgixovlwnjstetkj`, ฟังก์ชัน, ทริกเกอร์, โมดูลหลังร้านทั้งหมด, edge functions, โค้ดบอท Render) — ยังไม่ได้แก้อะไรในระบบจริง

> อัปเดตหลังพัฒนาเสร็จ (27 ต.ค. 2569): ชื่อตาราง/ฟังก์ชัน/โมดูลที่สร้างจริงบางส่วนต่างจากแผนในข้อ 3 — ดูรายละเอียดใน `02-design-and-test.md` ข้อ 2 · ทดสอบบนฐานข้อมูลจำลองและเบราว์เซอร์ (หน้าจอจริงของหลังร้าน) แล้ว · **ยังไม่ได้ติดตั้งในระบบจริง** รอเจ้าของอนุมัติตาม `03-enable-guide.md`

## 1. สรุปสั้น

- **ทำได้ และไม่ต้องรื้อของเดิม**: ทุกอย่างเป็นการ "เพิ่ม" (ตารางใหม่ `chat_*`, ฟังก์ชัน `chat_*`, โมดูลหลังร้านใหม่ 1 ตัว, ส่วนเก็บข้อความในบอท) ไม่มีการแก้ตาราง/ฟังก์ชัน/โมดูลเดิม และ **ไม่แตะ Webhook URL**
- **จุดที่ต้องระวังที่สุด (พบจากการตรวจ)**
  1. ระบบเดิม **รองรับ LINE OA เดียว** ทั้งบอท (secret/token จาก env) ฐานข้อมูล (`line_followers`, `app_secrets.line_channel_token`) และฟังก์ชัน `line-order` → หลาย OA ต้องมีทะเบียนช่องทางใหม่ และ **ห้ามใช้ token ของ OA หลักส่งหาผู้ใช้ของ OA อื่น**
  2. **คำสั่งซื้อเดิม (`orders`) ไม่ตัดสต็อกตอนสร้าง** (`_write_order` ไม่แตะสต็อกเลย) — สต็อกถูกตัดที่เดียวคือตอนขาย POS (`pos_checkout`) หรือออกเอกสารส่งของ/ใบเสร็จ (`doc_stock_sync`) → ออเดอร์จากแชทต้องทำเหมือนกัน และเชื่อม POS ผ่านทางเดียวที่ล็อกให้ทำได้ครั้งเดียว
  3. **ใบจัดของเดิมคือ PDF ที่หน้า "คำสั่งซื้อจากหน้าเว็บ" สร้างจาก `orders`** (`pick_slips`, 1 ใบต่อออเดอร์) → ออเดอร์จริงที่สร้างจากแชทจะเข้ารายการนั้นเองและใช้ปุ่ม "ปริ้นใบจัดของ" เดิมได้ (เรียกผ่าน `window.NattaWO`)
  4. มีทริกเกอร์ `orders_push_notify`: ทุกครั้งที่มี `orders` ใหม่ ระบบเด้งแจ้งเตือนเข้ามือถือพนักงาน → ตอนพนักงานกดยืนยัน จะเด้ง "ออเดอร์ใหม่ NT-xxxx" ด้วย (พฤติกรรมเดิม ไม่แก้)
  5. กดยืนยันออเดอร์ในหน้า "คำสั่งซื้อจากหน้าเว็บ" (`pending → done`) จะส่งการ์ด "ร้านยืนยันแล้ว" ให้ลูกค้าตาม `orders.line_user_id` ด้วย token OA หลัก → **ออเดอร์จากแชทของ OA อื่นต้องเว้น `line_user_id` ว่าง** กันส่งผิดช่อง
  6. ตารางสินค้า: 741 รายการ, SKU = `products.code` (UNIQUE), มีบาร์โค้ด 646, ราคา 738 — **คอลัมน์ `aliases` (ชื่อเรียกอื่น) มีอยู่แต่ว่างทั้งหมด** · ไม่มีสินค้าของใช้ทำความสะอาด → หลายรายการจะเป็น "รอตรวจ" ซึ่งเป็นพฤติกรรมที่ต้องการอยู่แล้ว
  7. ไม่มี `pg_cron` ในฐานข้อมูล → งานล้างข้อมูลเก่า (ถ้าต้องการ) ต้องให้บอททำ
  8. มีแชท/ผู้ช่วยอื่นกำลังแก้โมดูลหลังร้านอยู่ (skin, settings, school, stock, catsort, funcs แก้วันนี้) → โมดูลใหม่ **เพิ่มเป็นแถวใหม่** ใน `app_modules` ไม่ไปชนกับโมดูลอื่น
  9. **ตัวแอปที่ตอบลูกค้า (เมนู/รีเลย์/แอดมินรับเรื่อง) ผูกกับ `SUPABASE_URL` บน Render**: ถ้าตั้งค่านี้ แอปจะเริ่มทำงานและตอบลูกค้าตามแถว `app_config.line_bot` (ค่าจริงตอนตรวจ: `enabled: true` มีข้อความทักทายและลิงก์) → ฟีเจอร์ใหม่จึงใช้การเชื่อมต่อแยกชื่อ `CHATDRAFTS_SUPABASE_URL` / `CHATDRAFTS_SERVICE_ROLE_KEY` เพื่อไม่เปิดคำตอบของแอปโดยไม่ตั้งใจ

## 2. ระบบเดิมที่ตรวจ

| ส่วน | สภาพจริง | ผลต่อฟีเจอร์นี้ |
|---|---|---|
| **Webhook / บอท LINE** | LINE → `nattagroup-y.onrender.com/webhook` (Express, Render) ตรวจลายเซ็นด้วย secret เดียวจาก env · state อยู่ในหน่วยความจำ · อ่านรายการหลายบรรทัดแล้วแจ้งแอดมินได้ (ทำไว้แล้ว ปิดไว้) · `app:off` เพราะ Render ยังไม่มีรหัสฐานข้อมูล | ใช้ webhook เดิม เพิ่มตัวตรวจลายเซ็นหลายช่อง + ตัวเก็บข้อความ (ทั้งหมดปิดไว้ก่อน) |
| **Edge functions (17)** | `line-order` (การ์ดออเดอร์หน้าเว็บ/ยืนยัน), `line-bot` (ไม่อยู่ในเส้นทางข้อความแล้ว), `push-notify` (รับ url เฉพาะ `/` หรือ `/#หน้า`), `drive-backup`, `school-ai`/`photo-match`/`boss` (ใช้คีย์ AI ใน `app_secrets` ซึ่ง **ว่าง**) … | ไม่แก้ตัวใดเลย ใช้ `push-notify` เหมือนเดิม |
| **ออเดอร์** | `orders` (NT-nnnn, `status` pending/done/cancelled, `channel`, `line_user_id`, `school_name`…) + `order_items` (`product_id` เว้นว่างได้) · สร้างผ่าน `_write_order` / `place_web_order_svc` (หน้าเว็บ) หรือหน้าแอดมิน (`admin_next_order_no`) · เลขที่จาก `order_no_seq` (ล่าสุด 145) · ไม่มี CHECK บน status · ออเดอร์เดิม 127 ใบ ทั้งหมด `done` | ออเดอร์จริงจากแชทใช้โครงเดียวกัน (`channel='line_chat'`, `status='pending'`) จึงเข้าหน้า "คำสั่งซื้อจากหน้าเว็บ" และ "งานลูกค้า" เอง |
| **ใบจัดของ** | หน้า "คำสั่งซื้อจากหน้าเว็บ" (`weborders`) → ปริ้น/บันทึก PDF ลง `pick_slips` + bucket `pick-slips` + สำรอง Drive · เปิดใช้จากโมดูลอื่นได้ทาง `window.NattaWO.{print,save,open}` | โมดูลใหม่เรียก `NattaWO.print/save` ไม่เขียนซ้ำ |
| **สต็อก / POS** | `products.stock_qty` + `stock_moves` · `pos_checkout(p jsonb)` ตัดสต็อกตอนขาย (ไม่ตัดรายการบริการ/ไม่มี product_id) · `pos_void` คืนสต็อก · `doc_stock_sync` ตัดตอนออกใบส่งของ/ใบเสร็จ มีตัวกันตัดซ้ำตามสายเอกสารแม่ · **POS ไม่มีช่องดึงออเดอร์เข้าตะกร้า** | ออเดอร์/ดราฟต์ไม่ตัดสต็อก · เชื่อม POS ด้วยฟังก์ชันใหม่ที่เรียก `pos_checkout` ตัวจริง + ตารางล็อก 1 ออเดอร์ : 1 บิลที่ไม่ถูกยกเลิก |
| **สิทธิ์ (RLS)** | ทุกตารางเปิด RLS มีนโยบายเดียว `staff_all` (role `authenticated`) · `app_secrets`, `st_state`, `line_chat_state` ไม่มีนโยบาย = เฉพาะ service role · bucket: `pick-slips`, `project-docs`, `shop-docs`, `sale-files` (ส่วนตัว), `product-images` (สาธารณะ) · realtime: `orders`, `products`, `project_docs` | ตารางใหม่ให้พนักงาน **อ่านอย่างเดียว** เขียนผ่านฟังก์ชันที่มีประวัติเท่านั้น · ความลับช่อง LINE เฉพาะ service role · bucket ส่วนตัวใหม่ `chat-media` |
| **ลูกค้า LINE** | `line_followers`/`line_visitors`/`line_school_links` ไม่มีคอลัมน์ช่องทาง (OA เดียว) · `customers` ไม่มี `line_user_id` | แชทผูกลูกค้าด้วย (ช่องทาง, LINE userId) ในตารางใหม่ ไม่ปนกับของเดิม |
| **หน้าแอปหลังร้าน** | เชลล์ + โมดูลเป็นโค้ดในตาราง `app_modules` (32 แถว) โหลดตามลำดับ `seq` · ไม่มีหน้าแชท/ดราฟต์ | เพิ่มโมดูล `chatorders` แถวใหม่ (seq 65) ปิด-เปิดด้วย `enabled` ได้ |

## 3. สิ่งที่ต้องแก้/เพิ่ม

| ชั้น | เพิ่ม | แก้ของเดิม |
|---|---|---|
| **ฐานข้อมูล** (migration แบบเพิ่มอย่างเดียว) | `line_channels` (ทะเบียน OA + ความลับ) · `chat_threads` · `chat_messages` (ไม่ซ้ำด้วย channel+LINE message id) · `chat_drafts` (Draft Order, 1 ใบเปิดต่อ 1 ลูกค้า) · `chat_draft_items` · `chat_draft_events` (ประวัติ) · `chat_order_sales` (ล็อก POS) · ฟังก์ชัน `chat_ingest`, `chat_draft_apply`, `chat_draft_confirm`, `chat_draft_cancel`, `chat_order_pos_sale`, `chat_drafts_list`, `chat_draft_get` · bucket `chat-media` · realtime `chat_drafts` | **ไม่มี** |
| **บอท Render** | ทะเบียนช่อง + ตรวจลายเซ็นหลายช่อง (ช่องหลักยังเป็นเส้นทางเดิมทุกประการ) · ตัวอ่านบทสนทนาหลายข้อความ (กฎ + AI เลือกเปิดได้) · ตัวจับคู่ SKU · เก็บข้อความ/รูปเฉพาะที่เกี่ยวกับออเดอร์ · สร้าง/ต่อ Draft แบบไม่ซ้ำ · การ์ดแจ้งแอดมินมีเลข Draft · ช่องอื่นนอกจาก OA หลัก = เก็บอย่างเดียว ไม่ตอบ | `server.js` เพิ่ม hook (ปิดไว้) · เส้นทาง `chatOrders`→`project_docs` ที่ทำไว้รอบก่อน (ยังปิดอยู่) จะถูกข้ามเมื่อโหมดใหม่เปิด |
| **หน้าแอปหลังร้าน** | โมดูลใหม่ "ออเดอร์จากแชท" (รายการ + รายละเอียด + วางข้อความเอง + ประวัติ) | **ไม่มี** (เรียก `NattaWO`, `nattaLine`, `modal`, `toast` เดิมเท่านั้น) |
| **ใบจัดสินค้า / POS** | ปุ่ม "ใบจัดของ" (เรียกของเดิม) · ปุ่ม "ขาย POS" (ครั้งเดียวต่อออเดอร์) | **ไม่มี** |

## 4. เส้นทางข้อมูล

```
ลูกค้าพิมพ์/ส่งรูปใน LINE OA ──► Webhook เดิม (Render)
   └─ ตรวจลายเซ็น (ช่องหลัก = เส้นทางเดิม · ช่องอื่น = ตามทะเบียน line_channels)
   └─ บอทเดิมทำงานต่อเหมือนเดิม (เฉพาะ OA หลัก) · ตัวเก็บแชทเดินคู่ขนานแบบเงียบ ไม่ตอบ
        ├─ ข้อความทั่วไป ──► ทิ้ง (ไม่เก็บ ไม่สร้างอะไร)
        └─ ดูเป็นการสั่งของ (รายการ ≥2 บรรทัด / มีคำสั่งซื้อ+จำนวน / AI ช่วยอ่านประโยค)
              ├─ เก็บข้อความ+รูปที่เกี่ยวข้อง (รูป → bucket ส่วนตัว) · ไม่ซ้ำด้วย LINE message id
              ├─ แยกชื่อ/จำนวน/หน่วย/หมายเหตุ จากหลายข้อความในบทสนทนาเดียวกัน
              ├─ จับคู่ SKU: ชัดเจน→ผูก+ราคาจากสินค้า · ไม่แน่ใจ→"รอตรวจ" ไม่มีราคา
              └─ Draft Order (ต่อใบเดิมถ้ามีใบเปิดอยู่) ──► การ์ด LINE แอดมิน + เด้งมือถือพนักงาน
พนักงานเปิด "ออเดอร์จากแชท" ──► ตรวจ/แก้จำนวน/เพิ่ม/ลบ/เลือกสินค้า ──► [ยืนยัน]
   └─ สร้าง orders + order_items (NT-xxxx, pending) · ไม่ตัดสต็อก · บันทึกประวัติ
        ├─ ใบจัดสินค้า: ปุ่มเรียก NattaWO.print/save (ของเดิม)
        └─ POS: ปุ่ม "ขาย POS" → pos_checkout (ตัดสต็อกครั้งเดียวตรงนี้) · ล็อก 1 ออเดอร์ : 1 บิล
ไม่มีการส่งอะไรหาลูกค้าจนกว่าพนักงานยืนยัน (ข้อความแจ้งลูกค้าหลังยืนยัน = ตัวเลือก ปิดไว้ ต่อช่อง)
```

## 5. ข้อตัดสินใจที่ใช้ (ถ้าอยากเปลี่ยนบอกได้)

1. ออเดอร์จริงเริ่มที่ `pending` (ตรงกับหน้า "คำสั่งซื้อจากหน้าเว็บ" ที่ลูกค้าได้การ์ดตอนพนักงานกด "ยืนยัน/เสร็จสิ้น" เหมือนเดิม) — การยืนยันดราฟต์ = ตรวจรายการถูกต้องแล้วสร้างออเดอร์
2. **ราคา**: ใส่ให้เฉพาะบรรทัดที่ผูกสินค้าแล้ว โดยใช้ราคาในสินค้านั้น (ไม่ใช่การเดา) พนักงานแก้ได้ · บรรทัดที่ไม่ผูก = ไม่มีราคา ต้องให้พนักงานเลือกสินค้าหรือกำหนดราคาเองก่อนยืนยัน · ยังไม่คิดราคาโรงเรียน/ราคาตามระดับ (แก้เอง)
3. ข้อความ/รูปเก็บเฉพาะที่เกี่ยวกับออเดอร์ (ข้อความทักทายทั่วไปไม่เก็บ) · รูปอยู่ bucket ส่วนตัว ดูผ่านลิงก์ชั่วคราว · จำกัดชนิด/ขนาดไฟล์
4. AI อ่านประโยค: ปิดไว้ เปิดเป็นรายช่อง และต้องมีคีย์ AI บน Render · AI แค่แยกข้อความ ไม่กำหนดราคา ไม่ผูกสินค้าเอง
5. ช่อง LINE อื่นนอก OA หลัก: เก็บอย่างเดียว บอทไม่ตอบ (คำตอบ/เมนูของบอทเป็นของร้านนัฐภรณ์)

## 6. การทดสอบ และการติดตั้ง

- ทดสอบก่อนติดตั้ง: ฐานข้อมูลจำลองที่ใช้สคีมาเดียวกับของจริง (PostgreSQL จริงใน PGlite รวมฟังก์ชัน `pos_checkout`/`stock_adjust` ตัวจริง) + เซิร์ฟเวอร์บอทจริง + หน้าแอปหลังร้านจริงในเบราว์เซอร์ → ตั้งแต่ข้อความแชท → Draft → ยืนยัน → ออเดอร์ → ใบจัดของ → POS และตรวจว่า **สต็อกเปลี่ยนครั้งเดียว**
- ติดตั้งจริง **รอเจ้าของอนุมัติ**: (1) migration (2) โมดูล (3) ค่าบน Render — ทุกขั้นย้อนกลับได้ (ไฟล์ย้อนกลับมากับ migration)
