# เปิดใช้ "ออเดอร์จากแชท" (LINE OA Chat to Order) — คู่มือสำหรับเจ้าของ

ทำตามลำดับ · ทุกขั้นย้อนกลับได้ · **ยังไม่มีขั้นไหนถูกทำแล้ว** · ขั้น 1–2 แตะฐานข้อมูลจริง ขั้น 3 แตะ Render จริง · รหัสลับ (service role key) ให้ใส่ที่หน้า Environment ของ Render โดยตรง **ห้ามส่งในแชท**

ก่อนเริ่ม: อ่าน `02-design-and-test.md` หัวข้อ 6 (ความเสี่ยงที่ต้องตัดสินใจ) โดยเฉพาะข้อ 1 เรื่องการตัดสต็อก

## ขั้นที่ 1 — ฐานข้อมูล Supabase (โปรเจกต์ `mamlmgixovlwnjstetkj`)

1. เปิด SQL Editor รันไฟล์ `db/migrations/001_chat_drafts.sql` — เพิ่มตาราง `line_channels`, `chat_drafts`, `chat_messages`, `chat_draft_events`, ฟังก์ชัน `chat_*`, bucket `chat-media` (ส่วนตัว) · ไม่แก้ตาราง ฟังก์ชัน หรือโมดูลเดิม
   - ย้อนกลับ: `001_chat_drafts.reverse.sql` (ใช้ได้เฉพาะตอนยังไม่มีข้อมูลในตาราง `chat_*`)
2. รัน `app-patches/chat-drafts-module/apply.sql` — เพิ่มแถวโมดูล `chatorders` ใน `app_modules` **แบบปิดไว้** (`enabled = false`) · ถ้ามีแถวนี้อยู่แล้วจะไม่ทำอะไร
   - ย้อนกลับ: `reverse.sql` — ลบเฉพาะเมื่อโค้ดยังเป็นรุ่นที่ติดตั้ง (ถ้ามีคนแก้ จะไม่ลบและแจ้งเตือน)
3. ตรวจก่อนเปิด (ไม่บังคับ): `select name, enabled, seq from app_modules where name in ('weborders','chatorders');` ควรได้ `weborders` เปิดอยู่ และ `chatorders` ปิดอยู่
4. เปิดหน้าจอ (ทำหลังผ่านขั้นที่ 3 ของ Render แล้วเท่านั้น): `update app_modules set enabled = true where name = 'chatorders';` — รีเฟรชหน้าหลังร้าน จะเห็นเมนู **ออเดอร์จากแชท**

## ขั้นที่ 2 — ตั้งค่าบน Render (Environment)

ตั้งเฉพาะชุดนี้ **อย่าตั้ง `SUPABASE_URL` หรือ `SUPABASE_SERVICE_ROLE_KEY`** — สองตัวนั้นเปิดคำตอบอัตโนมัติของแอปให้ลูกค้าทุกคน (ดู `01-analysis.md` ข้อ 9)

| ชื่อตัวแปร | ค่า | หมายเหตุ |
|---|---|---|
| `CHATDRAFTS_SUPABASE_URL` | `https://mamlmgixovlwnjstetkj.supabase.co` | ไม่ใช่ความลับ |
| `CHATDRAFTS_SERVICE_ROLE_KEY` | (service role key ของโปรเจกต์) | **ความลับ** ใส่ที่ Render โดยตรง |
| `CHATDRAFTS_MODE` | `pilot` | ขั้นทดสอบ · ดูขั้นที่ 3 |
| `CHATDRAFTS_PILOT_IDS` | `U…` ของเจ้าของ | LINE user id ของคนที่ใช้ทดสอบ (คั่นด้วยคอมมา) |
| `CHATDRAFTS_ACK` | `off` | ขั้นนี้ยังไม่แจ้งลูกค้า |
| `CHATDRAFTS_AI` | `off` | ปิดไว้ก่อน |

หลังบันทึกและ Render ดีพลอยเสร็จ เปิด `https://<บอท>.onrender.com/health` ต้องได้ `"drafts":"pilot"` และ `"app":"off"` ถ้า `drafts` เป็น `no-db` แปลว่าต่อฐานข้อมูลไม่ได้ (ตรวจค่าข้อ `CHATDRAFTS_SERVICE_ROLE_KEY` และ `CHATDRAFTS_SUPABASE_URL`)

## ขั้นที่ 3 — ทดสอบกับ LINE ของเจ้าของเอง (โหมด pilot)

ลูกค้าคนอื่นไม่ได้รับผลใด ๆ ในขั้นนี้ (ระบบบันทึกเฉพาะ LINE ที่อยู่ในรายชื่อ)

1. จาก LINE ของเจ้าของ ส่งข้อความรายการ เช่น
   ```
   ไม้ถูพื้น=2
   น้ำยาล้าง=1แกลลอน
   ปากกาลูกลื่นน้ำเงิน 0.5=3 ด้าม
   ```
   **ต้องเห็น:** การ์ดในไลน์แอดมินทั้งสามคน (มีเลขร่าง CH-xxxx และปุ่มเปิดหน้าจอ) และการแจ้งเตือนในมือถือ · **ต้องไม่มี** ข้อความตอบกลับเข้าไปในแชทของเจ้าของ (รายการไม่ถูกตอบ)
2. เปิดหน้าหลังร้าน → **ออเดอร์จากแชท** → แท็บ "รอตรวจ" ต้องเห็นร่าง พร้อมรายการที่ต้องตรวจ
3. ตรวจรายการ: ผูกสินค้าจากข้อเสนอ ใส่ชื่อลูกค้า กด **บันทึก** แล้ว **ยืนยันเป็นออเดอร์** → เลข NT-xxxx · ยอดต้องตรงกับราคาในระบบ
4. กด **พิมพ์ใบจัดของ** → ใบจัดของเดิมขึ้น (ชื่อ รายการ เลขออเดอร์) · ออเดอร์ต้องอยู่ในรายการ "คำสั่งซื้อจากหน้าเว็บ" ด้วย
5. **ขายผ่าน POS** → ต้องตัดสต็อกตามจำนวนเพียงครั้งเดียว · กดซ้ำไม่ได้ (ขายซ้ำถูกปฏิเสธ)
   > ขั้นนี้ **ตัดสต็อกจริง** — ใช้ร่างทดสอบที่ตั้งชื่อลูกค้าเป็นการทดสอบ หรือยอมรับผลก่อนกด

ถ้ามีข้อใดไม่ตรง ให้ตั้ง `CHATDRAFTS_MODE=off` ทันที (ไม่มีการบันทึกข้อความเพิ่ม) แล้วแจ้งผลที่เห็น

## ขั้นที่ 4 — ใช้จริงกับลูกค้าทุกคน (ต้องอนุมัติ)

- ตั้ง `CHATDRAFTS_MODE=on` บน Render (ไม่ต้องดีพลอยใหม่)
- ตัดสินใจก่อนว่าจะเปิดสองอย่างนี้หรือไม่ (ค่าเริ่มต้นปิด):
  - `CHATDRAFTS_ACK=on` — ลูกค้าได้ข้อความ "ได้รับรายการสั่งซื้อแล้วค่ะ ร้านกำลังดำเนินการจัดสินค้า" **หนึ่งครั้งหลังพนักงานยืนยันเท่านั้น** และจะไม่ส่งระหว่างที่พนักงานกำลังคุยกับลูกค้า
  - `CHATDRAFTS_AI=pilot` หรือ `on` — ต้องมี `GEMINI_API_KEY` หรือ `ANTHROPIC_API_KEY` บน Render และมีค่าใช้จ่าย · เริ่มที่ `pilot`
- OA ที่สอง (ถ้าต้องการ): เพิ่มแถวในตาราง `line_channels` (`key`, `name`, `shop_label`, `channel_secret`, `channel_token`, `enabled = true`) แล้วตั้ง Webhook URL ของ OA นั้นเป็น `https://<บอท>.onrender.com/webhook/ch/<key>` · ความลับของช่องต้องใส่โดยเจ้าของ · ระบบไม่ตอบลูกค้าผ่าน OA ที่สอง

## ย้อนกลับ (ทำได้ทันที)

| ต้องการ | ทำ |
|---|---|
| หยุดรับข้อความเข้าร่าง | Render: `CHATDRAFTS_MODE=off` (บอทยังทำงานเหมือนเดิมทุกอย่าง) |
| ซ่อนหน้าจอ | `update app_modules set enabled = false where name = 'chatorders';` |
| ถอดโมดูลออก | รัน `chatorders` ใน `reverse.sql` (ลบเฉพาะถ้ายังไม่มีการแก้โค้ด) |
| ถอดตาราง | รัน `001_chat_drafts.reverse.sql` — ใช้ได้เฉพาะตอนยังไม่มีร่างในระบบ มิฉะนั้นเก็บตารางไว้ (ไม่กระทบอะไร) |

ไม่มีขั้นใดลบหรือแก้ออเดอร์ที่ยืนยันแล้ว ออเดอร์ NT-xxxx ที่สร้างไปแล้วยังอยู่ในรายการเดิม และยกเลิกได้ที่หน้า "คำสั่งซื้อจากหน้าเว็บ" ตามปกติ

## สิ่งที่ลูกค้าจะเห็น

- ระหว่างที่ร่างเปิดอยู่: **ไม่มีข้อความใหม่จากร้านเพิ่มเติมจากการทำงานของระบบนี้** · ข้อความที่บอทเดิมเคยตอบ (เช่น ขอบคุณ, ขอบคุณรูป) ยังทำงานเหมือนเดิม
- หลังพนักงานยืนยัน: ข้อความแจ้งหนึ่งครั้ง (ถ้าเปิด `CHATDRAFTS_ACK`)
- ไม่มีการส่งรายการหรือราคาให้ลูกค้าโดยระบบนี้
