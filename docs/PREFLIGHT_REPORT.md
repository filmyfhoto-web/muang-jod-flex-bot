# รายงานทดลอง: การ์ด LINE “ม่วงจดให้”

สถานะ: **TEST / ยังไม่เชื่อม production**

## สิ่งที่ตกลงแล้ว

- ใช้ LINE เป็นช่องทางหลัก
- บันทึกทุกครั้งต้องมีหน้าตรวจสอบและปุ่มยืนยัน
- การ์ดแสดงประเภท หมวด รายการ จำนวนเงิน เวลา และช่องทางชำระ
- ปุ่มแก้ไขเปิดหน้า LIFF และปุ่มยกเลิกต้องถามยืนยัน
- รองรับหลายรายการในข้อความเดียว และห้ามอ่านขนาด `60*100` เป็นราคา
- ใช้โปรเจกต์ Supabase เดิม แต่ตารางของระบบนี้ขึ้นต้น `mj_*`
- ไม่แตะหรือเชื่อมข้อมูล Film Shop
- ใช้แบรนด์ “ม่วงจดให้” และรูปน้องมะม่วงในหน้าและการ์ด

## ขอบเขตที่สร้างในรอบนี้

1. ตัวแยกข้อความรายรับ/รายจ่ายและหลายรายการ
2. Flex Message: ตรวจสอบก่อนบันทึก, จดสำเร็จ, สรุป, ยืนยันยกเลิก
3. หน้า TEST สำหรับลองพิมพ์ข้อความและกดทุกปุ่ม
4. หน้า LIFF: แก้ไข, รายการล่าสุด, สรุปวันนี้/เดือนนี้, หมวด
5. Soft delete เพื่อเก็บประวัติแทนการลบแถวจริง
6. SQL preview สำหรับ `mj_pending_batches`, `mj_transactions`, `mj_categories`, `mj_transaction_events`
7. Rich Menu mapping 8 พื้นที่

## สิ่งที่สมมติใน TEST

- ผู้ใช้จำลองคือ `TEST-U001`
- ระบบเติมคำว่า `TEST -` หน้ารายการที่บันทึกในโหมดจำลอง
- “งานวันนี้/รับงาน/งานลูกค้า” ถูกจัดเป็นรายรับเบื้องต้น
- รายการอาหารทั่วไปที่ไม่ระบุประเภทถูกจัดเป็นรายจ่าย
- ลิงก์และภาพการ์ดจะใช้โดเมนจริงหลัง deploy เท่านั้น

## ยังไม่เปิดใช้

- การส่งข้อความเข้า LINE OA จริง
- การรัน SQL กับ Supabase จริง
- การเข้าสู่ระบบ LIFF ด้วยบัญชีจริง
- การอัปโหลด Rich Menu จริง
- การถอดเสียงและอ่านสลิป
- ตั้งวงเงินรายหมวด

## ผลทดสอบอัตโนมัติ

- ผ่าน `14/14` กรณี
- ผ่านการแยกรายการเดี่ยว รายการหลายบรรทัด เลขไทย และข้อความไม่มีราคา
- ผ่านกรณี `60*100` และ `40*60` ไม่ถูกนับเป็นจำนวนเงิน
- ผ่านการยืนยันซ้ำโดยไม่สร้างรายการซ้ำ
- ผ่านการป้องกันผู้ใช้ TEST คนอื่นแก้หรือลบรายการ
- ผ่าน LINE signature และลายเซ็นลิงก์แก้ไข
- ผ่านเส้นทาง API `preview → confirm → summary`
- หน้า `/`, `/edit`, `/summary`, `/transactions`, `/categories` ตอบสถานะสำเร็จ

ระหว่างทดสอบพบว่าคำว่า “รูปติดบัตร” อาจถูกตีความเป็นช่องทางชำระด้วยบัตรเมื่อท้ายข้อความมี “พร้อมเพย์” และแก้ให้ช่องทางที่ระบุทั้งข้อความมีลำดับความสำคัญแล้ว

## เกณฑ์ก่อนเปิดจริง

- LINE signature ผ่านด้วย Webhook จริง
- LIFF ID token ระบุผู้ใช้ถูกต้อง และผู้ใช้อื่นเปิด/แก้รายการข้ามกันไม่ได้
- ตาราง `mj_*` อยู่ในโปรเจกต์ที่ถูกต้องและสิทธิ์ `anon/authenticated` ปิดอยู่
- URL ทั้งหมดเป็น HTTPS และรูปน้องมะม่วงเปิดได้จากภายนอก
- ทดสอบกดซ้ำ ยืนยันซ้ำ แก้ไข และยกเลิกซ้ำ
- สำรองฐานข้อมูลก่อนรัน SQL และมีวิธีย้อนกลับ
