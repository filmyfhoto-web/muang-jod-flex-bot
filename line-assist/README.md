# line-assist

> **สถานะ (20 ต.ค.):** webhook ของ LINE ชี้ที่บอท Render ตรง (ตรวจด้วย LINE API) จึง **ไม่มีข้อความผ่าน `line-bot` → ฟังก์ชัน `line-assist` ของ Supabase** ตอนนี้ — ตัวตอบนี้ (โค้ดใน `src/`, หน้า Reply Studio ใน `studio/`, ฟังก์ชัน SQL ใน `sql/`) ถูกใช้ **ภายในบอท Render** แทน: `stationery-bot/src/assist/` เป็นสำเนาของ `src/` นี้ (`node stationery-bot/scripts/vendor-assist.mjs`; เทสต์จับถ้าไม่ตรงกัน) และ `stationery-bot/src/assist-stage.js` อ่านค่าจาก `app_config.faq_bot` ตัวเดียวกับที่หน้า Studio บันทึก. ฟังก์ชัน Supabase `line-assist` ยังติดตั้งไว้ใช้ถ้าวันหน้าย้าย webhook กลับมาที่ `line-bot`; วิธีขึ้นระบบแบบนั้นอยู่ด้านล่าง (ค่า `line_webhook_prev` ของแอปคืนเป็นที่อยู่ Render เดิมแล้วเมื่อ 20 ต.ค. — ขั้น "ต่อสาย" ด้านล่างต้องทำใหม่ถ้าจะใช้ทางนั้น)

ตัวตอบลูกค้าของ LINE OA ร้านนัฐภรณ์ เชียงกลาง ที่อยู่ในระบบหลังบ้านของร้านเอง (Supabase) — **แทนบอท Render (`stationery-bot/`)** เพื่อให้เหลือบอทชุดเดียว หน้าตาและปุ่มเหมือนบอทของร้าน (`line-bot`) ทุกอย่าง

```
ลูกค้า → LINE → line-bot (ของร้าน: เมนู, คุยกับแอดมิน, ส่งเอกสารโครงการ, การ์ดออเดอร์, ริชเมนู)
                    │  ข้อความที่ line-bot ไม่ตอบเอง ส่งต่อ ("relay") ไปที่
                    ▼
               line-assist  ← ฟังก์ชันนี้ (แทน Render): เวลาเปิดร้าน, สั่งของ, อุปกรณ์การเรียน, ที่ตั้งร้าน ฯลฯ
```

**ไม่แก้โค้ดของ `line-bot` เลย** และไม่แตะสิ่งที่ line-bot ทำอยู่ (เมนูตอนเพิ่มเพื่อน/ทักครั้งแรกหลังเงียบ 1 ชม./พิมพ์ "เมนู", คุยกับแอดมิน → เจ้ปิ่น/หญิง/ฟิล์ม แล้วเงียบ 24 ชม., ส่งเอกสารโครงการ → เลข PJ-, การ์ดออเดอร์ NT-…, ริชเมนู 3 ปุ่ม) — เปลี่ยนแค่ "ที่อยู่ที่ line-bot ส่งต่อ" จาก Render มาเป็นฟังก์ชันนี้ (ค่า `line_webhook_prev`)

ทุกคำตอบเป็น **reply ในแชท (ฟรี ไม่นับโควตา)** ยกเว้นการ์ดแจ้งแอดมิน ซึ่งเป็น push (และ push สำรองตอน reply token หมดอายุ)

**แก้คำตอบเองได้ ไม่ต้อง deploy:** ใช้หน้า **Reply Studio** (หัวข้อ "Reply Studio" ด้านล่าง) — ลากวางกฎ แก้คำ/การ์ด/รูป ทดลองพิมพ์ในจอ LINE จำลอง แล้วกดบันทึก

## ตอบอะไรบ้าง

| ลูกค้าส่งมา | ผล |
|---|---|
| เวลาเปิดร้าน / สั่งของ (ลิงก์สั่งซื้อ) / ที่ตั้งร้าน | การ์ดคำตอบ |
| อุปกรณ์การเรียน 2-69 → ชื่อโรงเรียน | ถาม "โรงเรียนไหน" แล้วส่งลิงก์รายการอุปกรณ์ของโรงเรียนนั้น (29 โรงเรียน) |
| ขอบคุณ / สติกเกอร์ขอบคุณ | ตอบรับ |
| สั่งงาน โฟมบอร์ด ไวนิล ปริ้นงาน… / ขอถาม มีสินค้าไหม สั่งทำได้ไหม… | การ์ด "ต้องการติดต่อใคร" — รายชื่อและคำอธิบายใต้ชื่อ (เช่น "ร้านเครื่องเขียน") **ตามที่ตั้งไว้ใน line-bot**, ปุ่มส่ง "คุยกับ<ชื่อ>" ซึ่ง line-bot รับต่อเอง (ยืนยัน + เงียบ 24 ชม., พิมพ์ "เมนู" กลับมา) |
| รูป / ไฟล์ | "ขอบคุณค่ะ ได้รับรูป/ไฟล์แล้ว" 1 ครั้ง/10 นาที + แจ้งแอดมินทั้งหมด ไม่เกิน 1 ครั้ง/ลูกค้า/5 ชม. (ตั้ง `GEMINI_API_KEY` ถ้าอยากให้แยกสลิป — อ่านแค่ว่าเป็นสลิปหรือไม่ ไม่อ่านยอด) |
| ข้อความหลายอันรัว ๆ | ตอบอันเดียว (6 วินาที) |
| วันเสาร์ | ข้อความแจ้งร้านหยุด นำหน้าคำตอบแรกของวัน (ครั้งเดียวต่อคน) |
| อะไรที่บอทไม่รู้ (ชำระเงิน โปรโมชั่น ใบเสร็จ ราคาสินค้า ฯลฯ) | เงียบ ไม่แจ้งใคร — แอดมินเห็นแชทและตอบเอง |
| แอดมินพิมพ์ `ปิดบอท 2` / `เปิดบอท` / `โควตา` / `ไอดีฉัน` | ปิดบอททั้งร้านชั่วคราว / เปิด / ดูโควตา push / ดู LINE id |

ปุ่มลัดใต้คำตอบ = **ชุดเดียวกับที่ line-bot ใช้ใต้การ์ดเมนู** (อ่านจากค่าตั้งค่า `line_bot` เดียวกัน: สั่งซื้อสินค้า · ส่งเอกสารโครงการ · คุยกับแอดมิน · เวลาเปิดร้าน · สั่งของ · อุปกรณ์การเรียน 2-69 · ที่ตั้งร้าน พร้อมไอคอนของร้าน) ตัวนี้ไม่ตอบ "สวัสดี" เฉย ๆ (กันการ์ดซ้อนกับเมนูของ line-bot) — เปิดได้ด้วย `"greeting": true`

## ตั้งค่า

ตัวนี้อ่าน 2 แถวใน `app_config`:

- **`line_bot`** (ของ line-bot เอง — แก้จากหน้าตั้งค่าของร้านได้เหมือนเดิม): รายชื่อแอดมิน + คำอธิบาย (`admins`), `silence_hours`, `admin_label`, `old_chips`, `menu_style`, `links` — ตัวนี้ทำตามทั้งหมด จะไม่มีวันขัดกับ line-bot
- **`faq_bot`** (ของตัวนี้):

```json
{
  "mode": "admins",
  "admins": [
    { "name": "เจ้ปิ่น", "userId": "U…" },
    { "name": "หญิง",   "userId": "U…" },
    { "name": "ฟิล์ม",  "userId": "U…" }
  ],
  "chatLinkTemplate": "https://chat.line.biz/…?openExternalBrowser=1",
  "chatLinkLabel": "เปิดแอปตอบลูกค้า",
  "assets_base": "https://raw.githubusercontent.com/filmyfhoto-web/muang-jod-flex-bot/<commit เต็ม>/line-assist/assets"
}
```

- `mode`: `off` = ส่งต่อทุกอย่างให้บอทเดิม · `admins` = ตอบเฉพาะแชทของแอดมินในรายชื่อ ที่เหลือส่งต่อบอทเดิม (ช่วงทดสอบ) · `all` = ตอบทุกคน ไม่ต้องใช้บอทเดิม. ไม่มีค่า/ค่าผิด = `off` (ปลอดภัย)
- `admins`: ชื่อ **ต้องตรงกับชื่อใน line_bot** + LINE userId (`U` + 32 ตัว; ให้แต่ละคนพิมพ์ "ไอดีฉัน" กับ OA). ใครไม่มี id ที่ถูกต้อง จะไม่ถูกเสนอในการ์ด. **ไม่เก็บ id ไว้ใน git**
- ปรับได้: `quietMinutes` (ปกติตาม `silence_hours` ของ line_bot = 24 ชม.) · `alertEveryHours` (5) · `pictureReplyMinutes` (10) · `burstSeconds` (6) · `notify` (`false` = ไม่ส่งการ์ดแจ้งแอดมิน) · `paused` · `greeting` · `senderIcon` (ใช้รูปร้านเป็นอวตารผู้ส่ง — ปกติปิด เพื่อให้หน้าเหมือนข้อความของ line-bot)
- แก้ข้อความ/คำตอบ/โรงเรียนโดยไม่ deploy: ใส่ใน `content` (คีย์ที่ยอมรับ ดู `src/config.js`: `rules`, `schoolSupplies`, `greeting`, `thanks`, `holiday`, `contact`) หรือแก้ `src/data.js` แล้ว deploy ใหม่ — วิธีสบายสุดคือหน้า Reply Studio (ด้านล่าง) ซึ่งเขียนคีย์พวกนี้ให้
- `content.rules` (ถ้ามี) ใช้แทนรายการคำตอบที่มากับโค้ดทั้งหมด; ถ้าไม่มี บอทใช้ชุดที่มากับโค้ด (ผลเหมือนกัน มีเทสต์เทียบ)

Secrets (ตาราง `app_secrets` ที่ line-bot ใช้อยู่แล้ว): `line_channel_token` (มีอยู่แล้ว) · `faq_hook_key` (กุญแจร่วมระหว่าง line-bot กับฟังก์ชันนี้ อยู่ใน URL `?k=`) · `faq_forward` (ที่อยู่บอทเดิม ใช้ตอน `off`/`admins`) · `line_channel_secret` (ถ้ามี จะตรวจลายเซ็น LINE เพิ่ม) · `faq_notify_url` (เฉพาะถ้าเปิดตัวเสริมแจ้งแอดมินที่ถูกเลือก ดูข้างล่าง)

## Reply Studio — หน้าแก้คำตอบบอท

หน้าเดียวที่ใช้แก้บอทแทนการแก้โค้ด (`studio/`): ซ้าย = ชุดสร้างคำตอบ + รายการกฎ (ค้นหา เปิด/ปิด ทำซ้ำ ลบ ลากสลับลำดับ) · กลาง = แก้กฎ / ผังการตอบ / ข้อความทั่วไป / รายชื่อโรงเรียน / สถานะบอท / Export-Import · ขวา = จอ LINE จำลองที่ใช้โค้ดบอทตัวจริง (พิมพ์ลองแล้วเห็นการ์ดจริง ว่าตรงกฎไหน)

- **กฎ** = `{ชื่อ, เปิด/ปิด, ตรงแบบไหน (มีคำเหล่านี้ / พิมพ์ตรงทั้งข้อความ), คำที่ลูกค้าพิมพ์, คำตอบ 1–5 ข้อความ, ปุ่มลัดใต้คำตอบ}` เรียงจากบนลงล่าง **กฎแรกที่ตรงตอบเลย** (วางต่อจากขั้นขอบคุณ/เลือกแอดมิน/เอกสาร/ออเดอร์ และก่อนสินค้า เหมือนตำแหน่งเดิมของรายการคำตอบ)
- **ชนิดคำตอบ:** ข้อความ · การ์ด (หัวเรื่อง + ข้อความ + รูปการ์ตูน) · รูป (https) · สติกเกอร์ · Flex JSON · ไม่ตอบ (ใช้แทนหัวข้อที่ปิดไว้ — เงียบ ไม่ส่งต่อ)
- **เก็บที่ไหน:** `app_config.faq_bot.content.rules` — บอทอ่านรอบถัดไปทันที ไม่ต้อง deploy
- **บันทึกยังไง:** ผ่านฟังก์ชัน SQL ที่ล็อกไว้ (`sql/003_studio.sql`: `studio_load` / `studio_save` / `studio_restore` / `studio_set_mode`) เรียกด้วยบัญชี Supabase ของเจ้าของเอง ผ่านตัวเชื่อม (connector) ของ Claude — ฟังก์ชันไม่เปิดให้ `anon`/`authenticated`, **ไม่ส่ง LINE id ออกมาที่หน้า** (แทนด้วยค่าว่าง), เก็บประวัติ 30 เวอร์ชันให้กดย้อนกลับ, และบันทึกผ่านตัวตรวจเดียวกับที่บอทใช้ (`src/rules.js`) กฎที่ไม่ครบจะถูกข้าม
- **ข้อจำกัดของตัวเชื่อม:** หน้านี้เป็น Artifact ใน claude.ai (ไม่มีรหัสผ่านของตัวเอง) ใช้ได้เมื่อเปิดจากบัญชีที่เชื่อม Supabase ของร้านไว้ใน Claude; เปิดนอก Claude หรือไม่ได้เชื่อม = โหมดดูตัวอย่าง (ลอง/Export ได้ บันทึกไม่ได้)
- **สร้างใหม่/แก้ตัวหน้า:** `npm i --no-save esbuild && node studio/build.mjs` → `studio/dist/studio.html` + `studio/dist/img/*` แล้วเผยแพร่เป็น Artifact (declare `mcp` → Supabase → `execute_sql`)

## ขึ้นระบบจริง (ทำทีละขั้น ย้อนกลับได้ทุกขั้น)

1. **ตารางเก็บสถานะ** (เพิ่มอย่างเดียว ไม่แตะของเดิม): รัน `sql/001_st_state.sql`
2. **Deploy** ฟังก์ชัน `line-assist` — ไฟล์ใน `src/` ทั้งหมดวางแบนในโฟลเดอร์เดียว (`index.ts` เป็นตัวเริ่ม) และ **ปิด verify_jwt** (LINE/line-bot ไม่ได้ส่ง login มา; ความปลอดภัยตรวจในโค้ด: ต้องมี `?k=` ที่ตรง หรือลายเซ็น LINE ที่ถูก)
   - วิธีที่ใช้อยู่จริงบนโปรเจกต์ร้าน: `index.ts` ไฟล์เดียวที่ `import` ตัวจัดการ (`handler.js`) กับตัวเก็บข้อมูล (`store.js`) จาก `https://raw.githubusercontent.com/filmyfhoto-web/muang-jod-flex-bot/<commit เต็ม>/line-assist/src/…` (ตรึง commit) — อัปเดตโค้ด = push แล้ว deploy `index.ts` ใหม่ที่ชี้ commit ใหม่ (ย้อนกลับ = deploy ชี้ commit เก่า). ต้องให้ repo อ่านได้แบบสาธารณะ
   - รัน `sql/003_studio.sql` ด้วย ถ้าจะใช้หน้า Reply Studio
3. **ตั้งค่า** (SQL เดียว ไม่ต้องเห็นค่ากุญแจ):
   ```sql
   insert into app_secrets(key, value, updated_at) values ('faq_hook_key', replace(gen_random_uuid()::text, '-', ''), now()) on conflict (key) do nothing;
   insert into app_secrets(key, value, updated_at) select 'faq_forward', value, now() from app_secrets where key = 'line_webhook_prev' on conflict (key) do nothing;
   insert into app_config(key, value, updated_at) values ('faq_bot', '{"mode":"admins", "admins":[…], "chatLinkTemplate":"…", "assets_base":"…"}'::jsonb, now()) on conflict (key) do update set value = excluded.value, updated_at = now();
   ```
4. **รูปการ์ด**: `assets_base` ชี้ไปที่โฟลเดอร์รูปบน GitHub ที่ตรึงคอมมิตไว้ (ใช้ได้ทันที) — ถ้าอยากไม่พึ่ง GitHub: POST `{"action":"seed_assets","from":"<ที่อยู่โฟลเดอร์นั้น>"}` ไปที่ฟังก์ชัน (ใส่ `?k=`) → คัดลอกรูปเข้า Storage แบบสาธารณะ ได้ `assets_base` ใหม่กลับมา
5. **ต่อสาย**: ชี้ line-bot มาที่ฟังก์ชันนี้
   ```sql
   update app_secrets set value = 'https://<project>.supabase.co/functions/v1/line-assist?k=' || (select value from app_secrets where key = 'faq_hook_key'), updated_at = now() where key = 'line_webhook_prev';
   ```
   ตอนนี้ลูกค้าทั่วไปยังไปทาง Render เหมือนเดิม (ส่งต่อผ่านฟังก์ชันนี้, `mode = admins`)
6. **ทดสอบกับ LINE แอดมิน 3 คน** (ดูรายการด้านล่าง)
7. **เปิดทุกคน**: `faq_bot.mode = "all"` (ปุ่ม "สถานะบอท" ในหน้า Reply Studio ทำให้ได้ หรือ `select public.studio_set_mode('all')`) และให้ `line_bot.relay` เป็น `true` (ค่าปกติ) เพื่อให้ line-bot ส่งข้อความที่ไม่ได้ตอบเองมาที่ตัวนี้
   - ฟีเจอร์ของ line-bot ที่ **ตัวนี้ไม่ทำเอง** คือ การ์ดเมนูรูป (ตอนเพิ่มเพื่อน/ทักครั้งแรกหลังเงียบ 60 นาที/พิมพ์ "เมนู" = `menu_card`), ขั้นตอนส่งเอกสารโครงการทางแชท (ส่งไฟล์/`pd:` = `docs`), การ์ดใบสั่งซื้อ/การ์ดยืนยัน (ทำงานเสมอ) — ถ้าต้องการให้ลูกค้าได้ฟีเจอร์เหล่านี้ ให้ค่า `menu_card` / `docs` (และ `admin_pick` ถ้าอยากให้ line-bot เป็นคนรับการเลือกชื่อแอดมิน) ใน `app_config.line_bot` เป็น `true` — **ค่านี้เจ้าของ/หลังร้านเป็นคนสลับ ตัวนี้ไม่แตะ**. ถ้า `admin_pick` เป็น `false` ตัวนี้รับการเลือกชื่อและเงียบ 24 ชม. เองจากสถานะของตัวเอง (ไม่ซ้ำกัน: line-bot รับก่อนเสมอถ้าเปิดไว้)
8. ใช้ 1–2 วัน ไม่มีปัญหา → ลบบริการ Render และโฟลเดอร์ `stationery-bot/`

### ตัวเสริม: แจ้งแอดมินที่ถูกเลือก (ไม่บังคับ)
line-bot รับการเลือกชื่อเองและ **ไม่ได้แจ้งใคร** (แอดมินเห็นแชทใน OA ตามปกติ). ถ้าอยากให้คนที่ถูกเลือกได้รับการ์ด "ลูกค้าต้องการคุยกับคุณ" (ไม่มีข้อความลูกค้า ไม่เกิน 1 ครั้ง/ลูกค้า/คน/5 ชม.) ให้รัน `sql/002_pick_alert.sql` และตั้ง secret `faq_notify_url` ตามหัวไฟล์ — เป็น trigger เล็ก ๆ บน `line_chat_state` ที่แค่เรียกฟังก์ชันนี้หลังเขียนเสร็จ ถ้าพังก็ไม่กระทบการเขียนของ line-bot (ทดสอบแล้วทุกกรณี). เอาออก: `drop trigger st_pick_alert on public.line_chat_state;`

### ทดสอบกับแอดมิน (ขั้น 6)
- ส่ง "เวลาเปิดร้าน", "ที่ตั้งร้าน", "สั่งของ", "อุปกรณ์การเรียน 2-69" แล้วพิมพ์ชื่อโรงเรียน → ได้การ์ด + ปุ่มลัดชุดเดียวกับเมนูร้าน
- ส่ง "สั่งงานไวนิล" → ได้การ์ดเลือกคน (เจ้ปิ่น/หญิง/ฟิล์ม) → กดชื่อ → line-bot ยืนยันและเงียบ 24 ชม.
- ส่งรูป/ไฟล์ → ได้ "ขอบคุณค่ะ ได้รับรูป/ไฟล์แล้ว" และแอดมินได้รับแจ้ง 1 ครั้ง ส่งซ้ำไม่ซ้ำ
- พิมพ์ข้อความที่บอทไม่รู้ → เงียบ
- ตรวจว่าเมนู / คุยกับแอดมิน / ส่งเอกสารโครงการ / การ์ดออเดอร์ / ริชเมนู ยังทำงานเหมือนเดิม (ตัวนี้ไม่ได้แตะ)

## ย้อนกลับ (เร็วที่สุดก่อน)
- `update app_config set value = jsonb_set(value, '{mode}', '"off"') where key = 'faq_bot';` → ส่งต่อทุกอย่างให้ Render ทันที
- หรือคืนที่อยู่เดิม: `update app_secrets set value = (select value from app_secrets where key = 'faq_forward') where key = 'line_webhook_prev';` → line-bot ส่งตรงไป Render เหมือนเดิม

## ข้อควรรู้
- การ์ดแจ้งแอดมินเป็น push นับโควตารายเดือน (พิมพ์ "โควตา" ดูได้) เหมือนบอท Render; คำตอบทั้งหมดต่อลูกค้าเป็น reply ฟรี
- ข้อความที่ line-bot ตอบเอง (เมนูหลังเงียบ 1 ชม. ฯลฯ) ไม่มีประกาศวันเสาร์ — ประกาศจะมากับคำตอบแรกของตัวนี้
- ถ้า `assets_base` ยังไม่ตั้ง การ์ดจะไม่มีรูปมาสคอต (ข้อความยังครบ)
